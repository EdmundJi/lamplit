# 06 · 社会是怎么长出来的，以及怎么知道它长出来了

这一页记的是我们对"社会化模拟"的建构哲学，和一套用来验收的判据。

它和 [03](03-ideas.md) 的区别：03 是"以后想试试"的灵感清单，这一页是**方法**——先想清楚什么算数、
什么不算数，再去建。写得比较长，因为几个月后重新推一遍很贵。

## 一、出发点，以及一处修正

出发的直觉是：**社会化模拟的核心是构建社会契约**，而人类社会之所以能运作，是因为契约定义了收益函数。

这个直觉的方向对，但"**契约 = 整体收益函数最大化的结果**"这个具体形式，我们决定**不采用**，
有两个理由。

**第一，契约论本来就有两条线，我们要的是另一条。**

- **设计式**（霍布斯、罗尔斯）：契约是从某个原初状态推导出来的最优解。
- **演化式**（休谟、Lewis 的 convention、谢林点）：契约不是谁签的，是重复博弈里沉淀下来的惯例——
  **它之所以稳定，不是因为它最优，而是因为每个人都预期别人会照它做。**

卢梭那个区分在这里特别要紧：**volonté générale ≠ volonté de tous**（公意 ≠ 众意）。
把每个人的收益加起来得到的是众意。而且——**"定义收益函数"这个动作本身就是最硬的一处写死**。
我们说不想把东西写死，那就不能从写下一个全局目标函数开始。

**第二，也是更根本的：这个小镇的居民不是优化器。**

整个架构是"先做，后解释"（下意识 → deed → 事后解释 → 记忆 → 信念 → 改变下一次下意识，
见 [02](02-modules.md) 的「谁先动」）。一个最大化收益的 agent 是它的反面。
所以契约在这里不可能从优化推出来，只能从**被记住、被预期**里长出来。

于是我们采用这个定义：

> **一条社会规范 = 被足够多居民各自独立持有的、同一条信念。**

这个定义能直接落到现有机制上：信念就是带 `supersedesKey` 的记忆，我们从不写它的内容。
它同时也给了验收的抓手（见第七节）。

## 二、系统里已经有的契约零件

比想象中多。翻了一遍 `town/companion`：

| 已有的东西 | 契约论上是什么 |
| --- | --- |
| `workArrangements`（assist / delegate / takeover，提出 → 接受 → 终止，可审计） | **一份真正的契约**：两造、明示要约、明示承诺、可撤销 |
| `mayTend` / `mayManage` 来自被接受的安排 | **委托授权**——洛克的形状 |
| `cafeOperating` + 自己挂出来的营业时间 | **对不特定公众的长期承诺**（"开门是义务不是习惯"就是它的落地） |
| `needed > 1` 的项目 | **猎鹿博弈**，字面意义上的 |
| `members`（答应了） vs `contributors`（真做了） | 承诺与兑现，**违约就住在这两个字段的差里** |
| `relationships`（非对称） | 声誉 |
| 带 `supersedesKey` 的信念 | 居民可以形成"某人说话不算数"这类**规范性判断** |

结论：**基础设施不缺，缺的是让它们咬合。**

## 三、真正缺的只有一件事：居民不会承诺未来

**契约是对未来的主张。**而现在居民只能表达"此刻做什么"。决策提示词里甚至明确压着这条：

> `accept` 只用于现在有意开始的小行动。若只是想明天、改天或等有空再做，stance=consider，不应
> accept；没有具体未来日程时不要擅自预约日期。

这句当初是为了防空头支票，但它同时**取消了"承诺"这个东西**——不能说"明晚我来"，就没有契约，
只有当场的协作。

而且（2026-09-10 查证）：**`members` 被写入三处、被读取只有一处**（判断能不能选 `help`），
**全代码库没有任何一处比较过 `members` 和 `contributors`**。所以一个人可以答应参与、
然后一根手指都不动，**全镇没有任何机制会注意到**。

**（2026-09-10 补：这两样已经建好了，见本节末尾。）**

要做契约，只需要补两样，其余可以自然长出来：

1. **承诺对象**：谁、对谁、做什么、什么时候、谁看见了。
2. **到点比对**：规则只记录事实——"他说了 T 会来做 X；T 到了，他来了 / 没来"。
   **规则不判断这是不是背叛**——那是本人和旁观者各自的解释，而且两边可以不一致，这正是好的地方。

有了这两样，后面全是现成的：声誉走 `relationships`，规范走信念，制裁走"我下次不叫他了"
（体现在 `lend_a_hand` / `invite` 的对象偏好上），**都不用我们写**。

### 建成之后长什么样（2026-09-10）

`Promise`：谁、对谁、做什么、什么时候、谁看见了。到点比对只写一个事实——`came` / `did_not_come`，
没有第三种取值。结构里**没有** broken / betrayed / failed / trust 这类字段，写进任何人记忆的
句子里也没有评价词，两条都由测试钉着。

许诺必须**当面**：两个人此刻在同一个地方。当时在场的每个人各拿到一条自己视角的记忆。

然后是这一节和第四节交叉的地方——**两问都单独问**，都不进那个二十项菜单：

| 问句 | 什么时候问 |
| --- | --- |
| 你想不想跟眼前这个人，把一件事说定一个时候？ | 身边真的有人、一天最多一次、名下没有还没结清的承诺、镇上还有需要不止一个人的事 |
| 到了约好的时候，他在／不在那儿。你怎么想？ | 结清之后六小时内，问被承诺的人和当时在场的人 |

第二问的答案可以只是一次感想，也可以带 `supersedesKey` 变成对**那个人**的长期看法——
「某人说话不算数」就是这样成为他自己持有的看法的，而不是我们算出来的一个指标。

规则在这两处都只判断"此刻问这一句有没有意义"，不判断该不该许诺、该不该介意。

还有一件同源的、更便宜的事没做：**`members` 和 `contributors` 至今没有任何一处比较过**。
答应参与然后一根手指都不动，全镇仍然没有机制会注意到。

## 四、一条用钱换来的警告

"只要基础设施足够多，社会就会自然发展"——**2026-09-10 这一整轮是这个假设的直接反例。**

合作的基础设施建好了，然后：

```
create    被提供 342 次，选中 0
invite    被提供 285 次，选中 0
celebrate 被提供 1658 次，选中 0     ← 五件做完的东西，没有一件被拿出来给人看过
```

**基础设施本身什么都没发生。**让事情真的开始发生的是三件别的事：

1. **让处境可读**（门前留言板；把 75% 那个上限直接说成"剩下的得有人一起动手"）
2. **把问题单独问一次**——同一个模型、同一天，社交动作埋在二十项菜单里选中率≈0，
   单独问 `react` 时 **53% 说好**
3. **反射先动**，解释后补

所以对社会契约这条线，判据是：

> **一个从来没人被问过的义务，不会被履行。**

如果加了承诺机制却不加"他没来，你怎么想"这一问，它一定会变成第二个 `celebrate`——
机制完美，一千多次机会，零次使用。

## 五、经济学的位置：先不加钱

不是因为它不重要，是因为**货币是多边交换的解法，而六个人的镇子没有那个问题**。
加了钱它会立刻统治整个模拟，别的都变成它的附庸。

**真正让契约成为必需品的是稀缺，不是货币。**而这个镇现在几乎没有稀缺：
能量会自己回、没人会饿、咖啡免费且无限。

先让**已有的排他性**咬起来：

- **只有经营者能 `tend`** —— 这已经是一项服务垄断，只是还没人在意。
- **时间和身体** —— 一个人只能在一个地方，这是真稀缺，只是现在不痛。
- `livelihoodPressure` —— 这个字段声明了，**全代码库没有任何一处读过它**
  （写了没人读的第 10 个字段，见 [05](05-notes.md)）。要做经济，那是现成的位置。

**分工**方面有个很小、可能效果很大的改动：现在任何人给任何项目出力效果一样（只受 diligence 影响），
而 `Project.kind`（art / garden / gathering / quiet）和 `occupation` 都是现成的。
让"对口"的人出力更有效，专业化就有了回报——**而我们一个字都没写"谁应该做什么"**。
但注意它对验收的副作用，见第七节社会学那一栏。

## 六、"天眼"那个居民：给异常，不给数值

设想是给某个 NPC 开天眼——能看到所有人的数值、发现异常就报告，成为我们从内部观察世界的一部分；
像一个看得见却改不了的摩西。

这个想法要保留，但**必须改一处**，否则它会正面撞上这个项目最硬的一条规矩：
内部数值（`energy` / `social` / `dutyPressure` / `lastSocialAt` / `livelihoodPressure`）
绝不进入任何模型上下文——有两个测试按**字段名**在拦。

那条规矩不是洁癖：**数值进了上下文，模型就会像读表格一样推理**（"他 social 只有 23，所以他很孤独"），
而不是像人一样。

**改法：他看到的不是数值，是异常本身，以观察的形式。**

规则检测到异常（某人三天没跟任何人说过话；某人的计划连着失败；某个承诺到点没兑现），
然后把它作为**他注意到的一件事**交给他——「青叔这几天谁也没搭理」。
这正是 `salientPerceptions` 已经在做的事（规则把内部状态翻译成定性线索），
**天眼只是光圈更大：他能察觉别人身上的事，而别人察觉不到。**

这样他仍然是个人，不是一块仪表盘。**一个功能是"念出我们指标"的角色，
很容易变成开发者的传声筒而不是居民**，这是这个设计最大的风险。

至于"他改变不了现状"——结构上现在已经如此，谁也强迫不了谁。
但要让它成为悲剧而不是设定，他得**能试**：能预警、能被不信。
而"他说过 X 会发生 / X 到底发生了没有"——**这就是第三节那套承诺-兑现机制，一模一样。**
两条线在这里合流，这让我们更确信那是该先做的东西。

## 七、怎么验收

### 先定"什么样的判据算好判据"

| 门槛 | 说明 |
| --- | --- |
| **可证伪** | 必须能出否定结果，而且我们会信那个否定 |
| **不可直写** | 如果能写一条规则直接产出这个数，它就不算证据 |
| **可量** | 能从已导出的产物里算出来，不能靠读时间线"感觉挺热闹" |
| **能区分"活着"和"走时"** | 见下 |

第四条是 2026-09-10 用钱换来的。那天小镇达到了「每天至少 3 次一起做事」，但第 2–5 天的形状是：

```
01-02 16:04 / 01-03 16:04 / 01-04 16:03 / 01-05 16:03   同一个项目、同一分钟、同一批人
```

**数字达标了，读起来是台钟。**所以任何计数型判据都必须配一个**变异度**分量，
否则总能用一个定时器满足它。（[04](04-decisions.md) 里"别为了凑数把习惯变成定时器"说的就是这件事，
写进文档不等于自己不再犯——那一轮犯了四次单向指令。）

### 总目标

> **同一份种子跑两次，两次都长出一条我们从没写过的规矩；
> 而且这条规矩至少有一个居民能自己说出来。**

三个部分各自在防一件事：

- **同种子跑两次要不同** —— 防"其实是我们写死的"。每次都长出同一条，那是我们写的。
- **两次都要长出规矩** —— 防"那只是噪声"。
- **居民能自己说出来** —— 最关键的一半。
  **如果我们量到了一条规范，而镇上没有任何一个人说得出它，那它是我们的指标，不是他们的社会。**

### 尺子本身（2026-09-10 建好）

`NormDetector`（`backend/src/test/.../tools/`）。四个维度——搭伙、搭手、场合、互惠——
每一条要过四道闸：支持 ≥4 件、跨 ≥2 天、比它自己的零假设高 ≥1.5 倍、**不是台钟**。
另有一块 `beliefs` 统计"说得出来"那一半：信念数、其中关于别人的、有信念的人数、
以及**被两人以上各自独立持有的 key**（也就是本页第一节那个规范定义的直接量法）。

`Stage.MET` 这个状态**检测器自己永远到不了**：只有盲读的人在某个居民自己的话里读到那条
规矩，`withSpokenBy` 才推得动它。量到了规范而镇上没人说得出，那是我们的指标，不是他们的社会。

### 怎么判定「我们没写过」

不靠我们自己维护一张"我们写过哪些规则"的清单。那张清单会烂，而且那是我们在审自己的案子。
靠**对照跑**：同一个 `worldId`、同一个天数，把模型关掉。

> **规则单独就能长出来的东西，按定义就是我们写的。**

`NormDetector` 因此有一条减法：跑出来的候选，减掉纯规则对照跑的候选，剩下的才叫居民自己的选择。
这条减法同时替我们守住了一件事——**一把在纯规则跑上会亮的尺子，报的不是发现，是把我们自己的代码念回给我们听**。

### 第一次拿这把尺子量的结果（2026-09-10）

| 跑 | 事件 | 候选 | 减掉对照之后 |
| --- | --- | --- | --- |
| 模型跑 `venture-day2`，3 天 | 1269 | 4 | **2** |
| 纯规则对照 `venture-day2`，3 天 | 63 | 9 | —— |
| 纯规则对照 `venture-day`，3 天 | 63 | 10 | —— |

**对照跑长出来的"规矩"比模型跑还多。** 剩下那两条（「12 点前后咖啡馆里会凑起人来」、
「小川是会走过去搭手的那个」）强度分别是 1.58 和 1.50，刚够着 1.5 那条线。

这不是"镇上没有社会"，是**这把尺子现在量到的那几样，规则自己就做得出来**——
共同行动那一轮加的反射（`placeHabitLendAHand`、`comeRoundAgain` 那些）正是在产生"搭伙"和"搭手"。
要拿到真正意义上的候选，得先有**规则做不出来的那种事**：承诺、还回去、旁人改投。

顺带记一个静默失败点：第一版的配对键没有排序，对照里的 `weaver+gardener` 和跑里的
`gardener+weaver` 是两个字符串，减法减不掉。**第一次跑出来的"3 条"里有一条就是这么来的**——
一把本来用来防我们自我恭维的尺子，第一版自己就在自我恭维。现在有一个测试专门钉这件事。

### 第一次完整走完三步的结果（2026-09-11）

同一份种子 `norm-seed-1`，两次 2 天的模型跑（`qwen3.7-flash`），外加一次同种子的纯规则对照。

**统计这一半过了**：`AWAITING_SPOKEN_CHECK`。减掉对照之后，跑 A 剩 3 条、跑 B 剩 1 条，
而且**不是同一条**——跑 B 剩下的正是「互惠」（6/19 次搭手是还回去的），也就是本页最后一节
说"如果只立一条就立它"的那一条。

**然后盲测把它推翻了一半。** 两个没读过仓库的人各读一跑，只看事件，五条重合：

| 他们读出的规矩 | 跑 A | 跑 B |
| --- | --- | --- |
| 找人说话要先走过去打招呼 | #1 | #1 |
| "我先…"说出口就被接受，不必解释 | #2 | #3 |
| 谁先占谁用，后来者道歉让开 | #3 | #2 |
| 打烊之后不再接新单，大家收工 | #4 | #6 |
| 起头 → 别人添笔 → 叫大家来看 | #7 | #4 |

**三条链子各自都通，但没有一条是同一条规矩上的三段：**

| | 检测器量到 | 盲读者读到 | 居民自己说出 |
| --- | --- | --- | --- |
| 互惠 | ✅ | ❌ | ❌ |
| 占用权 | ❌ | ✅ 两跑都读到 | ✅ 阿满：「又是被安排座位…我好像总是那个配合的人」 |
| 打烊收工 | ❌ | ✅ 两跑都读到 | ✅ 小川：「每次都说收拾完就走，其实只是不想在打烊前显得狼狈」 |

**所以：没达成。**断点是尺子的维度，不是镇上没长出东西。

### 然后补了维度，而它第一件事是打自己的脸

按盲读补了 `spotRespect`（有主的位置别人绕不绕着走）。它需要世界记下"谁占了哪个位置"——
以前 `TownPlaces.claim` 一直在改状态，什么痕迹都不留，所以补了 `took_spot` / `left_spot`。

拿纯规则对照一量：**131 次落座，0 次坐了别人的位置，碰运气该有 35 次。**翻回去看：

```java
Comparator.<Position>comparingInt(p -> p.ownerId == null ? 0 : 1)   // 无主的排前面
```

**占用权是座位分配器写的。**两个独立盲读者读出来的"这镇上最清楚的规矩"，是把我们的代码
念回给我们听。

> **这是整轮里最重要的一次拦截。**没有纯规则对照，那天的结论会是"小镇长出了占用权规范"，
> 证据看起来无懈可击——两个互不知情的人都把它排在第一位。

顺着这条线回看那五条重合的规矩，至少四条是我们的代码（相遇机制、贡献与庆祝机制、
打烊后拒绝咖啡馆动作、座位偏好）。**"基础设施够多社会就会自然发展"这个假设，这一轮是
第二次被证伪**——第一次是机制建好没人用（第四节），这一次是机制建好而我们把它当成了社会。

### 那条"最重要的拦截"，自己还留着两个洞（2026-09-11）

把上面那条 `131 / 0 / 碰运气 35` 再翻一遍，它错了第二次，而且两处都是尺子自己造出来的。

**洞一：它从来没问过那个位置当时空不空。**它问的是"这屋里有没有别人的位置"，然后把这屋里
的每一次落座都记成一次"有机会而没坐"。可 `cafe-counter` 的主人阿禾几乎整天坐在吧台上，
`garden-plot` 的主人青叔在苗圃里。**大部分时候那些位置正被它们自己的主人坐着，没有人在绕开
任何东西。**把"当时确实空着，而且另有地方可去"作为前提补上去，这条维度才在问一件真事。

**洞二：一半的落座是玩家的小人做的。**中立对照 287 次落座里 146 次是 `self`，而"坐了别人的
位置"的 56 次**全部**是它。它背后没有 `ResidentMind`，只有 `CompanionRules`——模型跑和纯规则
跑里一模一样，它做的每一件事都是我们做的。

这个洞的后果比它看上去严重得多：留着它，**对照**那边的 `spotRespect` 强度被压到 1.21，低于
门槛 1.5，于是对照不产出候选，于是**减不掉**，于是同一条规律会从模型跑里再出来一次，头上顶着
"发现"两个字。去掉它，对照读出来是 81 次落座、0 次坐别人的、碰运气该有 22.8 次。

> 同一个错误连着犯了三次，换了三张皮：座位分配器的一行 `comparator`、时间线里少掉的
> `left_spot`、玩家小人的 146 次落座。**每一次它都不是伪造数据，而是让一件我们做的事看起来
> 像一件他们做的事。**

顺便记下第三件事：这条维度现在会**拒答**。`TownPlaces` 给非优先座位加了 30 分钟事件冷却
（为了不让座位事件淹掉时间线，它做到了），代价是导出的时间线记不全谁坐在哪——中立对照
287 次换位里有 52 次没有对应的 `left_spot`，照这份记录回放会得出"三个有主的位置九成时间
有人坐"。缺口大于 0 就不回答，比照着错的回放算一个数出来强。

### 三条链子对上过一次，而对上的那一条是我们写的

回头翻 run A 的时候发现，三条链子**确实对齐过一次**，之前没看见：

| 链子 | 说的话 |
| --- | --- |
| 尺子 | `whoJoins` / `weaver`：阿满是会走过去搭手的那个（6 次，去过 4 个人开的头，强度 1.8） |
| 盲读者 | 两个人都说阿满对自己"在这群人里的位置"有看法 |
| 阿满自己 | 「又是被安排座位，又是替人找补圆场。**我好像总是那个配合的人**，连休息都得看别人的脸色。」 |

验收要的就是这个：量得到、盲读得到、当事人自己说得出。然后拿纯规则对照一减——

**对照里阿满也是搭手最多的那个，而且正好也是 6 次。**

原因在对照里看得更干净：对照没有模型，**没有人许愿**，阿满"最先动手的事"是 **0 件**。
一件事她从来不是第一个碰的，于是她的每一笔贡献按定义都是"搭手"。她不是爱搭手，她是
**没有被安排过开头**。

减法照规矩把它拿掉了，拿得对。但这一条比前面几条都更值得记住，因为它同时是两件事：

> **一个警告。**三条链子全部对齐，仍然可以整条都是我们的代码。"当事人自己说得出"这一关拦不住
> 它——阿满说得又准又具体，还隔了一段时间用另一个键把同一句话写了第二遍。**人会为自己的处境
> 编出一套自洽的说法，处境是一个列表下标也照编不误。**

> **一个成功。**虚构架构那条环路（下意识 → 做了 → 事后解释 → 记忆 → 信念）**跑通了**，而且跑出
> 了一条稳定的、跨两次反思都没变的自我认知。缺的不是环路，是环路起点上那个"下意识"应该来自
> 她的处境，而不是来自 `w.residentStates` 的顺序和"谁被允许先许愿"。

这两条连起来，就是下一步该改什么：**别再动尺子了，去把"谁先开口""谁先动手"这些起点从写死的
顺序里拿出来。**尺子这一轮已经够用——它这几次都拦对了。

### 说出来的话为什么这么少：146 次反思，5 条信念

顺手量了一下两跑的记忆构成，这是"居民能自己说出来"这一半一直过不去的算术原因：

| | 反思 | 有 `supersedesKey` 的信念 | 转化率 |
| --- | --- | --- | --- |
| run A | 146 | 5 | 3.4% |
| run B | 151 | 2 | 1.3% |

而且这 7 条**全部是关于自己习惯的**（阿满的"配合的人"、周野的"顺手推稳桌子"、小川的"拿复习当
借口"），没有一条是关于"大家一般怎么做"的。

所以 06 第一节那个定义——"规范 = 被足够多居民各自独立持有的同一条信念"——在目前的产出速率下
**算术上就不可能达成**：六个人两天，一共只有两到五条信念，而且各说各的。

`sharedBeliefKeys` 恒为 0 的真正原因也在这里，不只是键不稳：阿满那两条键不同、**文本一字不差**，
改成比文本立刻能合并——但合并完仍然是同一个人的两条，跨人依然是 0。

这一节不提出改法，只把数摆在这儿：要么让反思更常落成信念，要么让信念能顺着"听说"传开。两条都
是主代码，等确认跑结束再动。

### 纯规则对照有一条它保护不到的边界

这一轮才看清：**纯规则跑里根本不存在的事件类型，对照永远减不掉。**

中立对照跑完，`greeting` 0 条、`cafe_closing` 0 条。不是巧合——打招呼是模型回答"要不要搭话"
才会发生的，打烊那句话是模型写的。于是任何建立在这两个通道上的维度，**结构上**不可能被对照
挡下来，减法给出的那声"干净"是假的。

所以"不可直写"这一关，在这些通道上只能靠**读代码**，不能靠减法。这不是对照方法的小瑕疵，是
它的边界：**对照只能证明"规则自己也会长出这个"，不能证明"规则没有在暗中决定这个"。**

### 谁先开口，一半是列表下标决定的

想在 133 条 `greeting` 上加一条"谁总是先开口"的维度——这是全镇数据最厚的通道，也正好是居民
说得出口的那种话（"总是我先开口"）。先读代码：

```java
for(ResidentState other:w.residentStates){   // 列表顺序
    ...
    return;                                   // 撞上第一个合适的就停
}
```

**站到谁面前，是我们的列表顺序决定的。**实测主动率（主动次数 / 出场次数）：

| 列表位置 | 1 阿禾 | 2 小川 | 3 知夏 | 4 青叔 | 5 周野 | 6 阿满 |
| --- | --- | --- | --- | --- | --- | --- |
| run A | 0.91 | 0.56 | 0.49 | 0.32 | 0.30 | **0.03** |
| run B | 0.76 | 0.39 | 0.68 | 0.35 | 0.12 | 0.26 |

run A 完全单调，run B 不是——所以列表顺序**有偏，但不是全部**，在场与否和模型的选择也在起作用。
结论两条：

1. **不加这条维度。**它的零假设得先把我们自己的遍历顺序建模进去，那就不是在量这个镇子了。
2. 两个盲读者都说阿满对自己"在这群人里的位置"有看法。run A 里阿满 36 次出场只主动过 1 次。
   **那个"位置"有一部分是一个列表下标。**相遇的候选顺序该和座位一样，用
   `(worldId, residentId, 时间桶)` 哈希定，而不是用 `w.residentStates` 的写死顺序。

### 同种子两次要"不同"这条判据，有一个前提没被满足过

模型温度是 0.2。「同种子跑两次要长出不同的规矩」这条判据只有在**模型本身有真实变异**时才有
鉴别力：两跑长出同一条，既可能是"我们写的"，也可能只是"模型太确定"。前者被对照挡住了，
**后者挡不住**。真出现这个结果时要照实说这条判据在这个温度下不成立，不能读成结论。

### `sharedBeliefKeys` 恒为 0，是尺子的问题

"规范 = 被足够多居民各自独立持有的同一条信念"这个定义，落地成 `supersedesKey` 的精确匹配。
实测：**阿满同一句话写了两遍，键是 `weaver配合者` 和 `weaver-配合者`**——一个人连自己的 key
都稳不住，跨人精确命中几乎不可能。所以这个 0 **不能读成"镇上没有规范"**，只能读成"这个量法
还不成立"。真要量，得比文本而不是比键。

`beliefsAboutOthers` 也一样偏窄：判定法是"文本里出现别人的名字"，而阿满那条谁的名字都没提，
却显然是一条关于自己在这群人里的位置的看法。

### 各学科具体量什么

**社会学（结构）**

| 条目 | 怎么量 | 现在能量吗 | 写死风险 |
| --- | --- | --- | --- |
| **规范 = 信念收敛** | ≥3 个居民各自独立在同一 key 下写下同向信念 | 要加指标，数据齐 | 低 |
| **分工** | 贡献在（人 × 项目 kind）上的集中度 | 能 | ⚠️ **高**：一旦加了 `kind × occupation` 加成，**这个维度就作废**，只能拿我们没写过的维度当证据 |
| **关系结构** | 已有 `relationshipAsymmetry`；要加"某几对稳定亲近、某几对稳定疏远"而非随机抖动 | 半 | 低 |
| **角色期待** | 服务请求是否偏向"上次真的做成的那个人" | 能 | 低 |

规范收敛这条有现成的反面可用：`MetricsExporter` 里已有 `sameTopicDivergence`
（同一件事被记成不同文本的比例），**把它翻过来就是规范形成**。

**政治学（权威与正当性）** —— 这里有整套判据里最漂亮的一条：

> **契约只改变签字的两个人；正当性会改变第三个人。**

所以 `takeover` 之后不看当事双方，**看别人**：服务请求有没有改投新经营者？有没有人还去找旧的？
**只有旁观者的行为跟着变了才叫权威转移**，否则只是一纸私约。今天就能量，
而我们完全没写过"别人应该改投谁"。

另两条：授权被拒之后有没有后果（`work_rejected` 事件已有）；
承诺被违反之后有没有**我们没写过的制裁**。

**经济学（不用钱的两条）**

- **互惠**：A 帮过 B 之后，B 后来帮 A 的概率**高于**帮别人的概率。
- **稀缺下的排序**：两人同时要那个只有一个人能占的东西时，怎么解决、解决方式稳不稳定。

**哲学（自由与自我认识）**

| 条目 | 怎么量 | 为什么它是"好结果" |
| --- | --- | --- |
| **解释与事实的落差** | `explain` 写的账 vs `deed` 记录的事实，由**没参与设计**的 agent 盲判 | **落差为零反而是坏消息**——那说明居民是台账机器。"先做后解释"要成立，就得有一定比例的**真诚但不准确**的自述 |
| **同境不同择** | 同一个 `decisionFingerprint` 出现多次时，选择的分布 | 全同 = 自动机；全随机 = 噪声；**要的是中间那段**。这是"活着 vs 走时"的量化形式 |

`decisionFingerprint` 在 `ResidentDirector` 里已经有了。

### 盲测的社会版

沿用已有的盲测纪律（[04](04-decisions.md)：*执行的人必须没有参与过设计*）：

> **给一个全新的、没读过仓库的 agent 看一段时间线，只问一句："这个镇上有什么规矩？"**

- 它读出我们量到的 → **规范真的在文本里**，不只在我们的统计里
- 它读出我们**没**量到的 → 更好，说明我们的指标还不够
- 什么也读不出来 → 就是没做到，无论指标多绿

### 如果只立一条：互惠

理由：它同时是社会学（关系）、经济学（交换的起点）、政治学（义务的来源）的共同底座；
**它不可能被一条规则写出来**（可以写"A 帮了 B"，写不出"B 后来自发地更愿意帮 A"）；
现有数据结构就能算；而且**它是契约的最小单位**——在任何人签任何东西之前，
社会先有的是"你欠我一次"。

而要让它有机会出现，需要的正是第三节那两样东西。**这条目标不是空悬的，
它直接指向下一件该建的东西。**
