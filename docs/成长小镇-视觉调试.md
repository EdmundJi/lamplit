# 小镇视觉调试与验收

小镇是 Phaser Canvas。DOM 断言通过不代表人物、建筑、碰撞或气泡正确。每次修改渲染、移动或场景切换，都应实际打开截图检查，并结合状态快照定位；不能忽略浏览器异常来让测试变绿。

## 一键重现，不依赖后端

在 `frontend` 目录执行：

```sh
pnpm town:assets
pnpm test:town:visual
# 边开发边查看每一步的浏览器画面
pnpm test:town:visual:ui
```

资产生成需要项目 `tmp` 目录已有的授权 LimeZu 素材包。生成结果不提交 Git，修改必须落在 `scripts/build-town-assets.py`，否则重建时会丢失。

视觉测试会自动启动 `127.0.0.1:5176`，所有业务接口使用测试数据，真实 Phaser 渲染器、真实资源文件、真实键盘与点击不替换。默认 Chromium，固定白天行程用于复现，时钟正常推进。可通过 `TOWN_BASE_URL` 连接已经运行的开发服务器。

测试覆盖：

- 街道首屏、真实键盘移动、NPC 通行、30 秒观察巡游与 Esc 返回。
- 实际走进家、退出恢复街道、淡入期间快速退出与重复进屋、面板最小化恢复、390px 手机布局。
- 寻路抵达独立咖啡馆后才开启对应的目标面板。
- 生成的房间 JSON 必须通过生产解析器；运行中 JS 异常和 HTTP 错误使测试失败。

## 去哪里看证据

- `test-results/town-visual/report/index.html`：Playwright 报告，带每一步截图与状态附件。
- `test-results/town-visual/runs/`：每个场景的 PNG、JSON、完整录像 `video.webm` 和 `trace.zip`。
- `pnpm exec playwright show-trace <trace.zip路径>`：查看动作、网络、控制台和当时画面。

开发者或 agent 应读取实际 PNG，检查：楼层是否接合、家具是否裁切完整、玩家是否被重复绘制、气泡是否压住其他气泡、手机按钮是否被挡。不要把“有 canvas”当作视觉验收。

## 连接真实后端

已经运行的服务可能来自旧分支。名册接口 404 时，小镇会显示居民服务未连接；不要把空街当作“没有好友”。

```sh
# 仓库根目录；沿用现有 .env.local，不输出其中的密钥
TOWN_BACKEND_PORT=8082 scripts/run-local-backend.sh
# 另一个终端，frontend 目录
DEV_API_TARGET=http://127.0.0.1:8082 pnpm dev --host 127.0.0.1 --port 5176
```

用本地测试账号登录，再访问 `/town/immersive`。也可以设置环境变量 `TOWN_EMAIL`、`TOWN_PASSWORD`，在 frontend 目录执行：

```sh
node e2e/town/inspect-live.mjs
```

脚本不拦截后端接口；每两秒输出一份真实截图和快照。可设置 `TOWN_HEADED=1` 看到浏览器，`TOWN_CAPTURE_FRAMES=30` 连续观察约一分钟，`TOWN_CAPTURE_DIR` 指定输出目录。账号凭据不写入截图脚本和报告。

## 开发探针

开发模式下控制台可执行：

```js
window.__town.describe()
window.__town.snapshot()
```

快照包括：玩家坐标与可控制状态、真实可站立判定（包含障碍）、角色屏幕坐标和可见性、活动中的场景、帧率、缺失纹理、窗口状态、JS 错误、Fetch/XHR 失败。室内时街道处于休眠，`activeScene` 才是当前画面；不能把街道的玩家坐标误认为室内位置。

`__town.walk()` 是引擎输入探针，仅用于快速定位；正式视觉旅程使用浏览器真实键盘。修改代码时先停止正在执行的整段验收，再重新运行，避免 HMR 切换场景污染正在记录的现场。

## 脱困与交谈回归（2026-09-06 追加）

两种小镇布局顶部常驻「脱困」（无确认弹窗）：取消寻路、交互、观察与房间切换，清除冻结和按键状态，验证家门口可站立后重置人物及镜头，并立即上报室外位置。无法恢复场景时重建引擎。任务数据及业务面板编辑不因脱困清空。

退出建筑保留进门前的位置；自己的后端 presence 只用于重连初始化，轮询不再直接改写正在游玩的角色。地图加载有超时和取消机制，迟到的回调不能覆盖后续脱困操作。

交谈时 NPC 暂停行走和环境搭话；用户告别后恢复日程。居民可因行程说明原因离开；小助/邮递员可通过当前模型回复的隐藏 `control: {type: "/interrupt", reason: "…"}` 发起告别，显示四秒后释放。控制与任务 actions 分离，不从用户正文或历史消息执行，未发送的聊天草稿保留。

新增浏览器回归使用真实 Canvas、鼠标、键盘和截图；API fixture 会回写室内 presence，避免原先固定空位置掩盖跨场景问题。模型 `/interrupt` 浏览器测试使用可控 SSE，后端解析与流式服务另有测试，不等同真实在线模型主动告别验证。

产物：`test-results/town-recovery-full`（完整旅程）、`test-results/town-recovery-interrupt`（专项截图与 trace）。

追加验收：前端小镇 572 条测试通过；后端 town 目录 204 项中 203 通过、1 个 opt-in 用例跳过，0 失败/错误；完整 14 条浏览器旅程通过，新增退出动画竞态与另外 2 条切换专项回归全部通过（共覆盖 15 条不同旅程）。TypeScript 与生产构建通过。产物另见 `test-results/town-recovery-transitions`。

## 公园镜头与学院出口（2026-09-06 追加）

镜头复现条件：Phaser `ScaleManager.refresh()` 不仅在尺寸改变时触发 `resize`，Canvas 的页面位置变化也会触发。原回调无条件按玩家上方 110 像素居中，而平滑跟随的目标在玩家上方 40 像素；刷新与跟随竞争，公园入口/下部没有街道镜头边界遮挡，因此更明显。可控布局刷新下旧版镜头静止时纵向振幅约 12.9 世界像素（公园顶部受到边界裁剪）；这不需要网络延迟参与。修复忽略未改变尺寸的刷新，跟随/观察/平移期间不再强制居中。

学院旧素材的出生点 `(320,344)` 正好落在出口区域 `x=272..368,y=344..384`。生成器改为 `(320,320)`；控制器只在主动移动进入新的出口区域时触发离开，兼容仍缓存旧地图的浏览器。四张地图均检查出生点不在门内、脚底可站立及出口路径，原先仅公共房间做这些检查的问题已补齐。室内键盘方向向量不再被当作只有 1 像素的目标距离，30/60fps 均按 180px/s 移动，点击寻路仍限制在目标点内。

Firefox 可重复验证（默认仍只跑 Chromium）：

```sh
cd frontend
./node_modules/.bin/playwright install firefox
TOWN_FIREFOX=1 ./node_modules/.bin/playwright test --config playwright.town.config.ts --grep '公园刷新布局|学院停留'
```

共享开发机拉取后需重新生成地图。可以只运行生成器的 `generate_room_maps()`，不必重新裁切授权图集；原始图集和生成结果继续不入 Git。

验收结果：双浏览器专项 6/6 通过（学院、普通页镜头、沉浸页镜头）；公园入口/下半区及既有进出建筑、点击、健身房位置回归 5/5 通过。产物位于 `test-results/town-camera-academy-verified` 和 `test-results/town-camera-room-regression`，含逐帧镜头坐标、截图与 trace。类型检查、生产构建和四张地图验证通过。网络响应在浏览器专项中受控，未将其等同于用户真实网络环境的全面诊断。
