# 更好的自己 · 全站前端重设计方案

日期：2026-09-05  
阶段：源码审计、产品参考研究、设计方向与结构提案；尚未进入前端实现。

## 1. 设计结论

建议把产品统一为一座「由真实行动慢慢建成的成长小镇」。以清晰、成熟的工作台承载日常操作，以小镇、伙伴和成长档案承载情绪与记忆。

品牌主张：**让每一步，长成看得见的生活。**

用户进入系统，应该自然理解三个问题：今天先做什么；这件事为什么值得做；我的努力留下了什么。所有页面围绕这三个问题组织，而不是围绕数据库和功能模块组织。

视觉冲击力来自深浅对比、场景尺度、排版主次和反馈节奏。日常任务区保持清晰；登录、今日场景、伙伴、小镇和里程碑承担品牌表现。高频页面不重复铺设巨幅宣传头图。

### 2.1 现有资产值得保留

- 产品主线已经完整：目标 → 周期任务 → 今日执行 → 经验与属性 → 复盘调整。
- 低压力机制明确：部分完成、延期、恢复计划与独自升级，具有差异化价值。
- 小镇把等级、属性和任务状态映射为建筑与人物，有成为品牌核心资产的潜力。
- 伙伴、称号、徽章提供情绪回报；无需为了重设计另造一套积分或养成机制。
- Vue、共享主题变量、Lucide、ECharts、Phaser 与 Rive 已形成可复用技术基础。

## 4. 方向比较与推荐

| 方向 | 视觉特征 | 优点 | 代价 |
| --- | --- | --- | --- |
| A. 成长手记 | 纸感、编辑式排版、少量线稿 | 安静成熟，阅读舒适 | 与现有小镇、宠物的连接偏弱，品牌场景不足 |
| B. 成长小镇 · 推荐 | 深森林绿、暖白、日光金；像素场景配现代 UI | 利用现有资产，行动可连接到可见生活，有独特记忆点 | 必须建立场景与控件的清晰边界，控制加载开销 |
| C. 未来成长舱 | 深色、发光图形、数据中心式构图 | 初看强烈，适合强调科技感 | 容易削弱低压力定位，现有美术迁移成本高 |

推荐 B。保留像素小镇的世界观，文字、表单、聊天和图表采用现代清晰的界面。全站共享色彩角色、比例、轮廓和动效节奏；场景中的像素美术保留自身表现方式。

## 5. 叙事与关键旅程

### 5.1 从初见到长期使用

1. **初见：我可以从很小的地方开始。** 登录页展示一栋亮灯的小屋与少量成长痕迹，主标题使用品牌主张，补充「从一件做得到的小事开始」。
2. **起步：选择适合我的生活节奏。** 引导保留方向、时间和起步任务，结尾明确展示将创建的内容及返回修改入口。
3. **每天：现在有一件值得开始的事。** 今日页先呈现首要行动，精力与时间用于调整建议。
4. **反馈：这一步被记录了。** 完成后展示已确认的结果、经验变化及关联成长维度；伙伴做一次短回应。
5. **回望：我正在形成自己的生活。** 属性解释积累，洞察解释一段时间的变化，小镇展示成果，个人页收纳身份。
6. **中断后：这里仍然欢迎我。** 延期或低精力状态提供缩小任务、调整安排和重新开始，不使用衰败场景惩罚用户。

### 5.2 完成一次行动的反馈顺序

```text
点击完成
  → 行内提交状态，防止重复点击
  → 服务端确认成功
  → 任务状态更新 + 简短结果说明 + 撤销入口
  → 有明确增量时呈现经验/属性变化
  → 可选伙伴回应或进入小镇查看

提交失败 → 保留原状态与内容 → 显示原因和重试
撤销成功 → 恢复任务与相关统计 → 反馈不再重复播放
```

不凭前端点击预先发放奖励；不将一次任务等同于建筑升级。建筑变化遵循现有等级与属性映射。没有精确增量时只显示「已记录」，不用猜测的数值制造反馈。

建议文案：完成「这一小步，已经记下了」；部分完成「已经推进的部分，也算数」；延期「换个时间，接着来」。奖励说明采用实际结果，避免每次都夸张庆祝。

## 6. 信息架构

### 6.1 桌面端

```text
更好的自己                 固定品牌标识，用户头像另置
├─ 行动
│  ├─ 今日                 /today
│  ├─ 目标                 /goals
│  └─ AI 助手              /ai
├─ 成长
│  ├─ 属性                 /attributes
│  └─ 洞察                 /insights
├─ 陪伴
│  ├─ 小镇                 /town
│  ├─ 伙伴                 /partners
│  └─ 好友与消息           /friends 及其子路由
└─ 账户区域
   ├─ 个人档案             /profile
   └─ 设置                 /settings
```

保留当前路由路径和深链接，先重组导航层级与页面内容。品牌标识从用户姓名缩写中独立出来，建议使用「路径进入一扇亮窗」的简单几何图形；16px 单色也能识别，后续单独验证。

顶部只承载当前上下文、必要操作及消息入口。AI 同时在目标编辑和复盘的具体位置提供入口，沿用现有生成、编辑、确认流程。

### 6.2 移动端

底栏使用「今日、目标、小镇、我的」。AI 从今日与目标的明确文字入口进入；「我的」作为移动导航集合，提供属性、洞察、伙伴、好友与设置的清晰列表。小镇保留好友与消息入口，聊天页可直接回到会话列表。

底栏选项的改变属于信息架构调整，后续原型需要验证 AI、洞察和消息是否仍易于找到。独自升级用户仍可进入自己的小镇，消息不抢占主位。

## 7. 核心页面结构

### 7.1 今日：行动与场景同屏

1440px 桌面设计基准：224px 侧栏，主区左右 32px 留白，内容最大宽度 1200px。首屏不强制展示所有统计。

```text
┌──────────┬───────────────────────────────────────────────────┐
│ 品牌     │ 今日 / 日期                         消息 · 账户    │
│          ├────────────────────────────┬──────────────────────┤
│ 行动     │ 今天，先向前一小步。       │  我的街角             │
│  今日    │ 状态：稳定 · 25 分钟 [调整]│  小屋 / 伙伴场景      │
│  目标    │                            │  一条真实成长摘要     │
│  AI 助手 │ 今天先做                   │  [去小镇看看]         │
│          │ 阅读 10 页                 │                      │
│ 成长     │ 来自「恢复阅读习惯」       │                      │
│  属性    │ [开始这一步]       [更多]  │                      │
│  洞察    ├────────────────────────────┴──────────────────────┤
│          │ 今天的安排             待行动 / 已记录             │
│ 陪伴     │ 任务 · 目标 · 时长                   [主操作] […]  │
│  小镇    │ 任务 · 目标 · 时长                   [主操作] […]  │
│  伙伴    ├───────────────────────────────────────────────────┤
│  好友    │ 本周留下的变化             [查看洞察]              │
│          │ 基于实际数据的一句摘要                             │
│ 账户设置 │                                                   │
└──────────┴───────────────────────────────────────────────────┘
```

以上任务与时间为布局示例，不是真实用户数据。场景约占首屏主区 35%，首要行动约占 65%。标题建议 36px，场景高度约 260–320px，保证常规任务在首屏可见。

移动顺序：页头 → 简短场景条 → 首要行动与状态调整 → 任务列表 → 成长摘要。场景条约 96–128px，不把桌面大画面等比缩放后压在任务上方。

首要任务按已有推荐逻辑选取；没有推荐时依据明确规则显示下一项待办，避免未经验证的「最佳任务」判断。无任务时主操作变为「安排一件小事」；全部记录后显示回顾入口。恢复计划只在相关状态出现。

### 7.2 全站页面映射

| 页面 | 本页要回答的问题 | 新结构与视觉主角 | 交互重点 |
| --- | --- | --- | --- |
| 登录 / 注册 / 找回 / MFA | 这里是什么，如何进入 | 品牌场景与清晰表单双区；移动端缩短场景 | 密码、验证码和错误可读，模式切换位置稳定 |
| 初始引导 | 从哪开始适合我 | 单问题步骤页；选择方向 → 时间 → 起步任务 → 确认 | 可返回修改，最后一步明确实际创建内容 |
| 今日 | 现在先做什么 | 首要行动 + 我的街角 + 任务列表 | 开始/完成主操作；部分完成、延期等保留在更多菜单 |
| 目标 | 我想去哪里，下一步是什么 | 目标列表与当前目标详情分栏；详情包含完成标准、周期任务 | 新建/编辑用统一抽屉；移动端采用列表到详情导航 |
| 属性 | 哪些能力留下了积累 | 五维概览 + 可比较明细条 + 来源说明 | 雷达仅辅助形状识别；精确数值和文本始终可读 |
| 洞察 | 最近发生了什么，下周如何调整 | 先展示可证实的变化摘要，再呈现趋势、日历、周复盘 | 徽章退到次级区域；无对比基线时不生成增长结论 |
| 小镇 | 我的行动如何变成生活 | 场景成为主画布；轻量 HUD、地点信息面板 | 提供返回自己、缩放、昼夜、键盘可用地点列表 |
| 伙伴 | 谁在陪我，如何照顾它 | 伙伴小屋大场景 + 主要互动；伙伴列表、商店为次级区 | 统一币值、价格、已拥有、不可购买状态 |
| 好友 / 详情 | 朋友最近怎样，如何联系 | 关系列表 + 最近动态；详情按近况、成长、伙伴排列 | 添加与申请收进局部区域；尊重既有可见性与独自升级 |
| 会话 / 私聊 / 群聊 | 和谁交流，最新消息是什么 | 桌面会话与聊天分栏；移动单页切换 | 草稿、失败重发、未读定位、键盘与输入框避让 |
| AI 助手 | 如何把想法变成可行动的内容 | 对话主区 + 按需出现的草案面板；历史单独收纳 | 草稿可编辑、可确认；保留流式输出与危机场景 |
| 个人档案 | 我已经成为怎样的自己 | 头像、称号、成长摘要形成个人名片 | 详细分析链接到属性与洞察，避免重复整页图表 |
| 设置 | 如何让系统符合我的习惯 | 外观、通知、隐私数据、账户分组表单 | 保留已有外观选择与持久化；危险操作明确隔离 |
| 后台 | 当前需要处理什么 | 共享颜色与控件基础，采用紧凑表格工作台 | 保留角色、MFA、审计与风险信息的清晰层级 |
| 独立桌宠窗口 | 陪伴是否自然且可控 | 透明窗口与伙伴动画；操作面板共享 UI 规范 | 拖动、收起、关闭及窗口边界独立验证 |

## 8. 统一视觉语言

### 8.1 色彩角色

主调采用深森林绿与暖白；日光金用于强调场景与里程碑。珊瑚色仅作为温暖的装饰色，错误使用独立语义红。

| 语义变量建议 | 浅色初稿 | 用途 |
| --- | --- | --- |
| `--bg-canvas` | `#F5F3EC` | 全局画布 |
| `--bg-surface` | `#FFFEFA` | 表单、任务、内容区 |
| `--bg-subtle` | `#ECEFE7` | 次级区域与选中浅底 |
| `--bg-inverse` | `#173D32` | 品牌场景底、重点区 |
| `--text-primary` | `#20372E` | 标题与正文 |
| `--text-secondary` | `#617069` | 次级说明 |
| `--text-on-inverse` | `#FFFDF5` | 深底文字 |
| `--action-primary` | `#255643` | 主按钮与关键链接 |
| `--accent-sun` | `#EBC76B` | 里程碑、光照、少量强调 |
| `--border-default` | `#D7DED4` | 控件与必要分隔 |
| `--status-danger` | `#B23B42` | 失败与危险操作 |

日光金按钮搭配深色文字。状态需同时提供图标或文字。五维属性固定各自的图表色与标签，不能跟随用户强调色互换含义。

深色采用绿黑画布、逐级提亮的内容表面和独立反色文字；不直接反转整页。夜晚小镇与 UI 深色模式分别控制。已有 ocean/plum/amber/graphite 等偏好通过语义变量兼容迁移，不静默删除用户选择。

### 8.2 字体、尺寸与构图

- 正文优先系统中文无衬线；中文标题使用相同字体，通过字重和尺度建立品牌感，避免正文与标题风格脱节。
- 登录品牌标题 48–56px；今日主标题 32–36px；一般页面标题 28–32px；分区标题 20–24px；正文 15–16px；辅助信息 13px。
- 移动端品牌标题 32–36px、页标题 26–28px。中文正文行高 1.6–1.75，数据与控件采用更紧凑行高。
- 数值采用等宽数字特性。长任务名、长用户名允许换行；截断时提供完整内容的可访问方式。
- 间距统一为 4、8、12、16、24、32、48、64px。内容分区主要用留白和必要分隔线区分。
- 控件圆角 10px，内容容器 16px，品牌场景 24px，胶囊只用于标签与状态；紧致偏好通过统一变量派生。
- 常规控件高度 44px，紧凑桌面表格可使用 36px；移动触控区按至少 44px 的设计目标处理。
- 图标继续使用 Lucide，统一线宽与 16/20/24px 尺寸。装饰插画、宠物与地图不混用为功能图标。
- 阴影集中用于浮层与真实层级变化；常规任务行不逐项加悬浮阴影。

### 8.3 场景与素材

小镇是主要环境语言，伙伴是角色语言，徽章是收藏语言。UI 共享轮廓、颜色角色与排版，场景资产允许保留媒介差异。

首期沿用已有 LimeZu 与伙伴资源；统一背景明度、裁切、展示容器和占画比例。需要新增素材时再制定镜头、像素密度、光向、色板与授权要求，不在本轮重画已有角色。

今日页使用轻量场景预览，进入小镇后才加载完整交互引擎。预览若为静态图，必须标识为场景预览；用户数据摘要在独立 DOM 中呈现，避免暗示图片实时反映全部状态。素材缺失时显示语义完整的替代视图。

## 9. 组件与状态规范

| 组件族 | 统一内容 |
| --- | --- |
| 应用壳 | 分组导航、上下文顶栏、移动底栏、账户入口 |
| 页面模板 | 工作台、沉浸场景、阅读分析、对话；共享标题和操作区 |
| 行动 | 任务行、状态标签、主操作、更多菜单、进度、撤销 |
| 编辑 | 输入框、选择器、日期时间、抽屉、确认对话框、字段错误 |
| 成长 | 经验摘要、维度标识、徽章、称号、伙伴展示、场景预览 |
| 数据 | 指标摘要、图例、时间范围、无数据解释、可读明细 |
| 反馈 | 行内保存、Toast、Banner、空状态、骨架屏、加载失败 |
| 浮层 | 弹窗、抽屉、菜单、提示、消息、桌宠的层级与避让 |

按钮区分 primary、secondary、ghost、danger，定义 normal/hover/pressed/focus/disabled/loading。输入框定义 empty/filled/focus/invalid/disabled/read-only。任务状态集中映射，兼容现有页面与小镇的状态差异，不以设计工作擅自修改服务端枚举。

每个页面至少覆盖首次使用、正常、数据密集、加载、空数据、局部失败与长文本。额外覆盖今日额度达到上限、撤销、过期任务、无伙伴、素材失败、独自升级、AI 流式中断、群聊不可用、MFA 错误与注销冷静期。

动效建议：控件反馈 120–160ms，面板 180–240ms，成长确认 400–600ms。一次操作只产生一个主要反馈源；粒子庆祝仅用于真实里程碑。减少动态时关闭位移动画与粒子，关闭动态时所有场景也需响应。

## 10. 响应式、可访问性与性能

布局初稿以 1440×900、1024×768、390×844 和 320px 宽度验证。桌面侧栏、平板收缩导航、移动底栏分别设计；断点随内容测试调整。小镇与聊天采用专门布局，不套用普通 `.page` 最大宽度。

验收目标：正文对比度至少 4.5:1；大字与关键非文本控件至少 3:1；键盘焦点清晰，弹窗支持焦点约束、Escape 与关闭后焦点返回。地图提供等价 DOM 地点/居民列表，图表提供文字与数值明细。放大到 200% 后核心操作仍可使用。

任务操作无需等待 Phaser/Rive 加载；场景懒加载，页面不可见时暂停动画与非必要轮询；高成本图表按需实例化并正确释放。目标是让装饰加载失败不影响任务提交、消息阅读与目标编辑。

性能基线在实施前记录。建议把代表性移动设备上 LCP≤2.5s、INP≤200ms、CLS≤0.1 作为体验目标，并记录测试环境；不能将本地一次运行当作真实用户指标。

## 11. 实施阶段与交付闸门

### 阶段一：视觉样板与关键原型

先制作今日桌面/移动、目标编辑、小镇、AI 对话、深色与空状态样板。验证品牌场景和真实复杂操作是否协调，再冻结核心变量与模板。此次文档已完成结构提案；高保真样板尚未制作。

原型验证任务：找到并开始今日任务、记录部分完成、撤销、从 AI 草案建立目标、找到周复盘、在小镇返回自己。成功条件是用户无需解释即可完成，且知道数据是否已经保存。

### 阶段二：全局基础迁移

改造 `styles/tokens.css`、`styles/global.css`、`shared/ui`、`UserLayout.vue` 与 `AdminLayout.vue`。建立旧变量到新语义的兼容映射、统一图标/控件/浮层；迁移而不清空外观偏好。将常驻操作指南转换为局部帮助。

### 阶段三：行动闭环

按今日 → 目标 → AI → 属性/洞察完成迁移。保留任务状态转换、额度、撤销、周期任务物化、AI 草稿确认等既有行为。同步修改必要的组件与端到端测试。

### 阶段四：场景与陪伴

迁移小镇、伙伴、好友、消息、个人档案与桌宠窗口。统一场景框架和数据反馈，检查独自升级、素材授权、无素材降级及移动端遮挡。

### 阶段五：收口

完成认证、引导、设置与后台细节；跑完整主题、屏幕、状态与键盘验证。对核心页面进行截图对比，并执行项目适用的类型、构建与行为测试。扫描残余硬编码颜色，区分应迁移的 UI 值与应保留的美术色。

### 11.1 首期边界

首期包含结构、视觉、交互呈现及现有功能整合。实时街区协作、新货币、新排名、新任务算法和建筑新规则不属于视觉重构的必要条件，另行评估。原有认证、隐私、任务与奖励规则是迁移约束。

### 11.2 全站完成定义

- 页面映射表中所有页面均有一致的布局和状态规范，不只完成首页。
- 今日第一行动在代表性首屏可见；常用操作有文字且状态明确。
- 品牌场景、伙伴、图表、表单和后台可被识别为同一产品。
- 浅色、深色、现有强调色、紧凑模式与减少动态不出现明显断层。
- 小镇缺素材、数据失败或动画停用时，核心任务流程仍可完成。
- 核心行为回归通过，关键断点无操作遮挡；视觉 QA 留存截图与问题记录。

## 12. 下一轮的设计重点

下一步应先制作「今日页 + 目标页 + 小镇页」的高保真样板，同时给出今日移动版与深色版。这组样板覆盖行动效率、复杂编辑和品牌场景，足以验证方向是否能支撑整个系统。方向稳定后再全面迁移组件与页面。

当前推荐方向为成长小镇；品牌名称保留「更好的自己」，低压力、可恢复、陪伴与真实成长保持为设计主线。
