# 小镇交互动画：近身接触与双向回应

本轮根据用户反馈聚焦两处：喝咖啡时出现的长手臂线，以及人物之间粗糙的相遇表现。保留现有小镇、人物身份和日程，在同一套生产交互中改进动作。

## 素材依据

| 素材包 | 已核对的资源 | 设计用途 |
| --- | --- | --- |
| Modern Interiors | `2_Characters/Character_Generator/0_Premade_Characters/32x32/Premade_Character_32x32_01.png` 等预制角色；与当前 c01 等角色表一致 | 保留发型、肤色、服装，使用原人物抬物动作组合饮用和轻示意 |
| Modern Interiors | `1_Interiors/32x32/Theme_Sorter_Singles_32x32/12_Kitchen_Singles_32x32/Kitchen_Singles_32x32_394.png` | 原生咖啡杯实际18×18像素，手持显示9×9；已接入资产生成器的 `coffee_cup` 帧 |
| Modern Exteriors | 原邮递员、向导角色表及街道家具 | 同一动作网格，但部分人物表宽1854而非1792；帧列数由纹理实际宽度计算 |
| Modern Farm | `Farmer_Generator_Pieces/Tools/32x32/Tool_Watering_Can.png` | 独立水壶与水流层，不绑定农夫身份；后续浇水动作可用 |
| Modern Office | 办公场景家具图块 | 可用于摆放和坐姿接触设计，不作为本轮喝咖啡动作来源 |

原人物表有坐姿、电话、阅读、拾取、抬物等多类动作，不能把所有行为都当作站立姿态的整体旋转。也不能把 Farmer 完整浇水表直接覆盖玩家，因为那会更换人物外观。

外部动作参考：[Stardew Valley 饮用动作帧](https://stardewvalleywiki.com/File:Drinking_sprites.png)。本项目使用自己的授权素材，借鉴的是近身持物与短暂停顿的动作表达。

## 咖啡：去掉伸长线

旧实现把桌面杯子与人物固定手点直接连成一条线，且允许距离操作点52px就开始使用。站位、桌面高度和身体姿态并未对齐，所以线条承担了本来应由人物走近和伸手完成的距离。

新实现把站位设在桌右侧（相对桌脚中心 `+41,-3`），实际到达10px范围内才激活。杯子从桌边接触点交给原角色的手，杯子位置直接绑定经过图像核对的帧内手点，不再绘制手臂连接线，也不旋转整个人物。

使用原角色表 **row 11 / lift**，左向抬杯主要是 cols32→33→34，对应局部手点 `(6,54)→(7,48)→(11,44)`；杯中心放在手点左4、上2。col35会抬得过高，经过接触图检查后排除。这里是用抬物帧组合出的饮用表达，素材并没有专门命名的原生喝杯动作。

| 时间 | 动作 |
| --- | --- |
| 0–0.30s | 停稳并面向桌子 |
| 0.30–0.75s | 原人物伸手，杯仍在桌面 |
| 0.75–1.05s | 接住杯子，抬向嘴边 |
| 1.05–2.00s | 短饮，轻微倾杯 |
| 2.00–2.50s | 放低一档，留一口呼吸 |
| 2.50–3.40s | 再喝一小口 |
| 3.40–4.40s | 降回同一个接触点 |
| 4.40–5.40s | 杯交回桌面，手臂收回、恢复原待机 |

取消会恢复原人物帧和原动画，释放设施占用；完成才更新使用状态。原人物表采用实际列数，覆盖56列居民和57列邮递员等情况。

## 人物之间：先有距离，再有回应

- 点击人物后沿可走地面寻找约44px的接近点。家具挡住某一侧时换另一侧，不再把玩家目的地设成对方脚下。
- 路遇先停步互相面向，留350ms稳定姿态。
- 一方轻示意并说一句，另一方随后回应。短示意只借用原人物抬物动作的准备段，不抬到头顶。
- 两人的台词不同时堆出，较长台词按字数延长停留。
- 结束前有一个转身收尾，再返回原日程；键盘离开、正式对话或设施使用可以取消未发生的回应。
- 回到日程时继续避开家具；被阻挡会重新规划路径。

相遇使用已有名册和已有可说内容，不增加模型调用，不制造人物关系结论。

## 后续素材机会

Farm 的独立工具图为5376×288，第三行 `y=192,h=96` 是56个96×96水壶/水流帧；右、上、左、下各14帧，前6帧准备，后8帧浇水循环。它能解决当前水壶和水滴过于程序化的问题，但仍需要逐方向校准手部锚点。本轮先保存这一资源依据，没有把未校准的工具动画接到所有人物上。

## 模块边界与验收

`coffee-motion.ts` 管咖啡的身体帧和杯子接触；`social-motion.ts` 管社交距离与阶段；设施占用、存储与日程仍在原模块。各文件保持小型职责模块，不把逻辑重新塞回主引擎。

验收必须看放大后的实际 Canvas：杯子是否贴手、是否遮眼、拿放是否交接在同一点；再看两人是否有间距、是否真的先后回应、取消后是否遗留动作。函数测试用于守住距离、身份和状态恢复，不替代视觉检查。
