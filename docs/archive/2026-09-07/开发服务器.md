# 共享开发服务器

把一台机器（这里是作者的 Mac）当成大家都能连上来联调和调试的开发服务器。
前后端都跑在容器里，源码从宿主机挂进去，**改完自动生效**——协作者不需要在自己机器上装
Java 21 或 pnpm，只要能访问这几个端口就行。

配置在 `deploy/compose.dev.yaml`，总控在 `scripts/dev-server.sh`。

---

## SSH 开发入口与 Git 同步

### 少量开发者公网体验入口（2026-09-07）

入口：`http://39.106.137.127:15173/town/immersive`。使用系统自己的注册/登录；当前入口是 HTTP，无额外入口口令，请使用独立体验账号，不复用其他服务密码。

链路：北京 `frps:15173` → `frp-gateway` 独立客户端 → `192.168.0.104:5173`。前端同源代理 `/api/v1`；此映射不开放数据库、日志面板或远程调试端口。公网链接本身不限制访问者人数。

独立客户端配置位于网关 `~/.config/frp/growth-town.toml`（权限 600），认证信息不入仓库。用户服务 `growth-town-frpc.service` 已启用，支持重启后恢复及掉线重连：

```sh
ssh frp-gateway 'systemctl --user status growth-town-frpc.service'
ssh frp-gateway 'journalctl --user -u growth-town-frpc.service -n 30 --no-pager'
ssh frp-gateway 'systemctl --user stop growth-town-frpc.service'
ssh frp-gateway 'systemctl --user start growth-town-frpc.service'
```

停用并取消自启：`ssh frp-gateway 'systemctl --user disable --now growth-town-frpc.service'`。不影响原有 SSH 和其他 FRP 代理。

### 日常代码同步

当前共享开发机为 `ssh pub-mac-mini`，项目目录 `~/code/personal_study`。
本机先启动已配置的隧道：

```sh
ssh -fN mac-dev
```

随后打开 `http://127.0.0.1:15173/town`（沉浸模式为 `/town/immersive`）。这里连接的是远端开发容器；本机临时 Vite 端口不作为共享开发验收地址。

代码通过 Git 同步：本地提交并推送开发分支，远端确认无未保存修改后执行 `git pull --ff-only origin feat/town-mvp-knowledge-propagation`。远端有改动时先保存并审阅，禁止直接覆盖。Vite 与后端源码轮询会自动生效。

像素素材不入 Git。生成器变更后，需要在远端用已有授权素材包执行 `python scripts/build-town-assets.py`（Python 环境需 Pillow），再核查房间地图与图集。迁移文件发布后不改校验和，后续使用增量迁移。

## 1. 它和 `deploy/compose.yaml` 的区别

| | `compose.yaml`（原有） | `compose.dev.yaml`（本文） |
| --- | --- | --- |
| 后端怎么来 | `COPY backend/target/*.jar`，**要求你先在本机构建好** | 挂源码，容器内 `spring-boot:run` |
| 前端怎么来 | `COPY frontend/dist/`，nginx 托管静态文件 | Vite dev server，带 HMR |
| 改代码 | 重新构建 + 重新打镜像 | 存盘即生效 |
| 调试 | 无 | JDWP 5005、MySQL 对外、网页日志面板 |
| 用途 | 类生产部署 | 联调 / debug |

**两套共用同一批数据卷**（`growth_mysql_data` 等），所以来回切不会丢库；但端口会打架，同一时刻只开一套。

## 2. 启动

前置：`.env.local` 已存在（`cp .env.example .env.local` 后替换示例值），Docker 在跑。

```bash
scripts/dev-server.sh up
```

首次启动后端要下 Maven 依赖、前端要装 node_modules，**几分钟内接口才会通**，用 `scripts/dev-server.sh logs` 看进度。
之后每次启动都是秒级——依赖都在命名卷里。

> 切过来之前先停掉本机自己跑的 `pnpm dev`(5173) 和 `mvnw spring-boot:run`。
> 脚本会做端口预检，被本机进程占了会直接告诉你是哪个。

常用命令：

```bash
scripts/dev-server.sh urls              # 打印发给协作者的地址
scripts/dev-server.sh logs backend      # 跟某个服务的日志
scripts/dev-server.sh status            # 各服务状态 + 端口
scripts/dev-server.sh restart backend   # 重启
scripts/dev-server.sh down              # 停掉（数据保留）
```

## 3. 端口

全部可在 `.env.local` 里改（`DEV_WEB_PORT` / `DEV_API_PORT` / `DEV_DEBUG_PORT` / `DEV_LOGS_PORT`）。

| 端口 | 是什么 | 谁用 |
| --- | --- | --- |
| 5173 | 应用（Vite dev server） | 所有人。`/api/v1` 由 Vite 同源反代到后端，**cookie 不用做任何跨域配置** |
| 8080 | 后端直连 | curl / Postman，绕过前端 |
| 5005 | JDWP 远程调试 | IDEA / VS Code，见 §5 |
| 3306 | MySQL | 数据库客户端，见 §6 |
| 9999 | 网页版日志面板（dozzle） | 不想 ssh 的人 |
| 9000 / 9001 | MinIO API / 控制台 | 对象存储 |

协作者用 `http://<这台机器的局域网IP>:5173`，**不要用 localhost**——那在他们机器上指向他们自己。
`scripts/dev-server.sh urls` 会把 IP 填好打印出来。

## 4. 热更新是怎么做到的

两侧都**不能用 inotify**：源码是从 macOS 通过 bind mount 挂进 Linux 容器的，
文件系统事件跨不过虚拟机边界，`inotifywait` 一类的工具在这里一律收不到通知。所以两侧都走轮询。

**后端**：`deploy/dev/backend-entrypoint.sh` 每 2 秒扫一次 `backend/src`，有改动就 `mvn compile`；
Spring devtools 监视 `target/classes`，编译产物一变就重启应用（它自己的 FileSystemWatcher 本来就是轮询实现，所以这一侧天然可用）。
编译失败不会打断服务，应用继续跑在上一份能用的字节码上，错误会打在日志里。

改动落到页面上大约 5~15 秒（编译 + 重启）。改 `.yml` 配置同理。

**前端**：Vite 的 `server.watch.usePolling`，由 `VITE_DEV_CONTAINER=true` 触发（见 `frontend/vite.config.ts`）。
本机直接 `pnpm dev` 时这个变量不存在，行为完全不变。

**容器里的依赖目录与宿主机是隔离的**：`frontend/node_modules`、`backend/target`、`~/.m2` 都用命名卷盖住了
bind mount。这是必须的——rollup / esbuild 装的是平台相关的原生二进制，macOS 那份在 Linux 容器里跑不起来；
`target` 隔离则让容器和你本机的 `./mvnw` 各编各的，不会互相覆盖。

## 5. 远程调试（JDWP）

后端以 `-agentlib:jdwp=transport=dt_socket,server=y,suspend=n,address=*:5005` 启动，**不挂起**，
所以没人连的时候服务照常跑。

- **IntelliJ IDEA**：Run → Edit Configurations → `+` → Remote JVM Debug，Host 填这台机器的局域网 IP，Port 填 5005。
- **VS Code**：`.vscode/launch.json` 里加一个 `"type": "java", "request": "attach", "hostName": "<IP>", "port": 5005`。

**同一时刻只能有一个人挂上去。** 断点会阻塞整个 JVM——你在断点上停住，其他人的请求也一起卡住。
人多的时候先在群里说一声。

调试的代码版本必须和服务器上跑的一致，否则断点会错行。改完等日志里出现重启完成再挂。

## 6. 直连数据库

```bash
scripts/dev-server.sh db          # 直接进容器里的 mysql 客户端
```

或者用自己的客户端连 `<IP>:3306`，库名 / 用户名 / 口令在 `.env.local` 里。

小镇这套系统**查表就能验收**，不用开画面：

```sql
-- 谁知道什么、从谁听来的、传到第几手、这一手说成了什么样
select k.npc_code, k.hops, k.learned_from, k.salience, k.retold_text
from town_npc_knowledge k where k.town_user_id = ? order by k.hops, k.npc_code;

-- 玩家的事实必须是模糊化过的：这里查出来的文本不该出现任何阿拉伯数字
select payload from town_fact where town_user_id = ? and subject_kind = 'PLAYER';

-- 小助（GUIDE）必须全是 no_relay，且不该作为任何一条的 learned_from 出现
select count(*) from town_npc_knowledge where learned_from = 'GUIDE';
```

## 7. 造数据与重置

```bash
scripts/dev-server.sh seed        # 通过公开 API 造一份演示数据（复用 smoke-api.sh）
scripts/dev-server.sh town        # 清掉今日的小镇模拟锁，让传播链在下一次 cron 重算
scripts/dev-server.sh reset-db    # 清库重来（二次确认；Flyway 会重跑全部迁移）
```

关于 `town` 这条：小镇的夜间流水线按 `(用户, 当地日期)` 幂等——这是**故意的**，
否则重跑一次亲密度和相遇计数就多累加一轮。所以想在同一天反复调试传播链，必须先删掉
`town_society_run` 里那把锁。开发环境把两个 job 的 cron 调成了每 5 分钟一次
（`DEV_TOWN_SOCIETY_CRON`），删完锁等一会儿就有新结果。

## 8. 给协作者的须知

1. **这不是生产环境。** 数据随时可能被 `reset-db` 清掉，不要往里放任何真实的个人信息。
2. **口令都在 `.env.local` 里，那个文件不进版本库，也不要转发。**
3. **小镇的像素素材（LimeZu）是买断授权、不可再分发的**，不在版本库里，
   由宿主机的 `frontend/public/assets/town/` 挂进容器。不要把这些图片拷出去。
4. **AI 默认是 mock**（`QWEN_PROVIDER=mock`）。要连真实模型得在 `.env.local` 里配 key，
   注意那会产生真实费用。
5. 后端只有一个 JVM，**断点会卡住所有人**，见 §5。
6. 端口只在局域网内可达。要让外网的人进来，请用内网穿透（frp / Cloudflare Tunnel 之类），
   **不要直接把 3306 和 5005 暴露到公网**——那两个端口没有任何额外的鉴权保护。
