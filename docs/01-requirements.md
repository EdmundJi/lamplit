# 01 · 我们想做的小镇

这是一个从兴趣出发的陪伴式小镇。用户开着网页学习、工作，小镇也在过自己的日子。

> 这个功能，能不能让我更愿意和这个小镇一起度过今天？

我们想保留三种感觉：**陪伴感**让人愿意开着它，**生命感**让居民有自己的生活，**故事感**让相遇和记忆慢慢产生后续。

## 第一版

先做一个用户小人、四名 NPC 和一条小街。每个用户有自己的世界。

- 第一次打开是“搬进来”：居民已有习惯、关系和一点过去，有人正在做事。
- 用户选一项 Todo 开始专注，小人自己找位置学习；休息和换地方也只需要表达意图，不用操纵它走路。
- 用户不操作，小人照样会学习、喝水、休息、散步、回家，有自己的节律。
- 用户像小人脑子里突然出现的想法。明确安排优先执行，“想看看花”这样的随想可以择机实现，并简单反馈。
- NPC 能记住经历、形成看法、互相聊天。信息通过实际相遇传递，允许没听说、误解、忘记或改变主意。
- 晴雨、昼夜、室内外声音和少量生活动作，让它适合放在旁边长时间陪伴。
- 回来时可以看看小人的简短日记，不必补读所有对话或处理一堆未读消息。

真实 Todo 仍由用户确认完成。小人自动读书或专注计时结束，不代表用户完成了任务。用户几天没来，也不需要补做照料或面对惩罚。

## 生命感从哪来

第一版做出来之后，最明显的欠缺是居民像屏保：四个人各自挑一个动作演一下，看不出他们在过日子。我们讨论后认为缺的不是地图面积，而是三样东西。

**归属。** 现在全镇只有一个 `home`，所以晚上四个人挤在同一个房间；咖啡馆那张长桌被标成“可用”之后，再没有任何代码把它改成“被占用”。没有人拥有任何东西，也就没有“回自己家”、“这是我的位置”、“今天想坐窗边但已经有人了”。地点要变成两层的数据：地点里有具体位置，位置有主人、有容量、有状态。后端只描述结构与归属，像素画在哪由前端定，两边靠 id 对齐——这样美术可以随便重摆而不动规则。

**链条。** 生活是有前后依赖的：菜吃完了才去买，市场关门就买不到，买不到晚饭只能凑合。物品要有真实的状态和存量，链条要允许断——断了才会有意外，意外才是故事的来源。相比之下，“去买菜二十分钟”这种只有意图和时长的行为永远不会出事，也就永远不会有故事。

**离场。** 上班的人应该从地图上消失，而不是在街上站一天。早上街空了，傍晚陆续回来。不在场的人比在场的人更有说服力。

断掉的链条只写进日记，不在画面上喊。用户几天不来，只补算最近一小段真实生活，更早的时间把存量和需求重置到合理值——不编造离线剧情，也不让人回来面对一地鸡毛。

先把现有四个人活透。之后可以由我们手动设计和加入常驻居民，但模拟不会因为一句“想招人”就自动生成人物；新来的人也要有自己的经历、性格、生活方向与拒绝权。

**工作首先是一种社会常识。** 居民会觉得自己需要有一件能长期做的事来维持生活，也会在无所事事、反复被打断或觉得付出没有意义时重新考虑它。这里不做金钱、饥饿、房租、竞争或每日工作指标；休息几天、互相帮助、把照看花园理解成工作都可以成立。压力进入居民的长期考虑，不替他们指定答案。

**职业和职责可以改变。** 咖啡馆店主可以发现自己不喜欢这份工作、暂时停下来或转去做别的事。新职业先复用读写、制作、交谈和外出等已有动作；缺少设备或场地时，只能形成需求和准备，不能由一句话直接创造已经营业的新店。多数居民会受人格、习惯和关系牵引，继续过相对稳定的生活；少数偏离是允许发生的结果，不是程序必须促成的剧情。

**社会安排需要真实同意。** 帮工、委托经营和正式接手是不同的职责与权限。双方可以各自理解不同、反悔或重新协商，但实际使用设备、承担职责或转移经营权必须有可追溯的明确同意。经营者可以单方面停止自己的劳动；世界不会因此自动指定继任者，咖啡馆暂时无人服务也是有效结果。

## 人物到底怎么 loop

**LLM 是每名 NPC 的大脑。** 思考、是否工作、休息、睡觉、社交、继续手头的事或收店，都由该居民结合自己的经历和当下情境选择。规则负责时间积分、移动、设备、容量、权限与动作结果，不按 `energy`、`social`、`duty` 阈值替人自动选择行动。

最初的循环只有一个决策入口：

```java
if (r.plan != null && !at.isBefore(r.plan.endsAt())) { complete(...); }
if (r.plan == null) choose(w, r, at);
```

**当时计时器到期是唯一能让人重新做决定的事。** 手上有没过期的计划时，有人在等他、有人跟他说话、他要的东西没了，全都进不来。这是"死板"的根，也是责任感打断不了、三杯咖啡全被放弃的同一个原因。另外 `travel` 是假的——瞬移到街上站 12 秒再瞬移到目的地，**走路这个最日常的生命感来源被压缩掉了**。

对照 [Generative Agents](../references/README.md) §4.3.1：每个时间步感知世界，判断「继续当前计划还是反应」，反应之后**从被打断的时刻起重新生成计划**；而且计划是递归分解的，一天的粗纲到小时到 5–15 分钟。[Humanoid Agents] 补的是反馈闭环：动作做完要评估它有没有满足需求、改变情绪，据此更新后面的计划。

这暴露了计划、反应与反馈三处问题；解决它们时，认知选择仍归各自的模型：

**持续意图与当前动作分开。** 居民由模型决定长期想做什么、现在做什么，以及是否打断、恢复、推迟或放弃。规则保存动作进度和剩余时长，执行已经选择且合法的安排。去倒杯咖啡以后，回来还知道原本在做什么，不等于程序替他决定一定回来继续。

**反应也属于认知。** 世界变化和安排到期可以提供重新思考的机会；有没有比手头更要紧的、要不要回应等候的人，由该 NPC 的模型判断。时间每一步照常积分，但规则不能因为责任感或社交数值跨过阈值，就自动把居民拉去服务、聊天或睡觉。

**反馈进入经历与体感，不暴露仪表盘。** 生理、心理数值只在模拟内部保存和变化，不直接进入模型上下文。正常范围的状态省略；只有显著异常的体感才用“很累”“难以集中”这类定性描述告知居民，不附分数、阈值或指定动作。真实时间、地点、设备状态和眼前发生的事仍可作为外部事实进入感知。居民怎样理解经历、是否改变后续安排，交给模型。

**模型失败时不另造一个规则大脑。** 合法且仍可执行的已有安排可以继续；否则中性等待。失败回退不编造新的承诺、感悟、社交意图或生活决定。

产品里的昼夜仍跟随用户的真实时区。内部精力按经过的时间、昼夜与实际动作持续变化，睡眠恢复来自实际执行的睡眠；这些规则模拟身体，不替居民决定何时休息或睡觉。四名 NPC 都从可调整的 23:00–07:00 睡眠习惯开始，没有永久夜猫豁免；进入时间窗只告诉模型“到了平常睡觉的时间”，由本人决定收尾、继续或睡觉。偶尔晚睡可以发生，但要来自当时的安排。加速时间只在开发与验证中使用，不能改变普通运行的生活节律。

两篇论文都承认智能体过度礼貌与合作。我们的「允许往坏了长」是有意的分歧，不因为参考论文而动摇。

## 让他们自己产生秩序

上面那些机制如果只是被写死的规则，做出来的还是剧本，只不过换了个说法。真正想要的是这种东西自己长出来：

> 老板跑出去做自己的事，回来顾客抱怨等待时间有点长，老板写入记忆，自己反思发现自己不够尽职，于是后来就越来越少在工作时间出去。熟人经常在喝完咖啡后让老板倒水，老板后面慢慢主动提供水，预测用户的需求。

所以**经历会留下后续，而人格不必永远固定**。内部状态可以随真实经历缓慢、有界地变化，反思也能形成新的看法；但内部数值不直接提供给模型，更不能作为替居民选择行动的闸门。模型依靠自己的记忆、信念、情境与必要体感继续思考。

**必须允许往坏了长。** 这是判断这件事是真涌现还是假涌现的唯一标准。如果责任感只能升不能降，那是个棘轮——你已经知道结局，只是不知道第几天到。同一套机制必须也能长出一个越来越懒散的老板：他可以逐渐不再把店里的事放在首位；自己的读书小聚一次次被打断，反思出来的结论完全可能是"我为这家店牺牲太多"。**能长出我们没预料到的结果，才算数。**

**重复发生的事会变成预期。** 熟客喝完咖啡总要水，老板数着数着就开始提前倒上。这是一种存在他自己记忆里的预期，由模型决定是否据此行动，可能学对也可能学错——从两次巧合里学出一条并不存在的规律，然后一直端来别人不想要的水，这是人会犯的错，不该被防住。

世界需要保留**社会行为的真实经历与后果**，而是否开口、怎样解释、下一步怎么办由模型决定：

- 等待时长、谁在等待、过去怎样相处，都有真实记录
- 不满是否形成、是否说出口，由当事人结合情境决定
- 抱怨被实际听见后，才可能进入各自的记忆与后续理解
- 重复经历可以形成预期，预期也可能被下一次经历推翻
- 被照应或被冷落的经历可以改变关系，但不自动触发亲近或疏远动作
- 亏欠可以被记住、重新解释，也可以被忽略

**这条设计有吞吐量前提。** 「熟人喝完咖啡要水」这种模式要重复五到十次才能和巧合区分开。四个人的小街、模拟只在打开页面时推进，一天大概产生个位数的咖啡事件——这些东西在真实节奏下根本没机会长出来。所以加速跑那一批不是锦上添花，是这条设计的前提；数值悄悄漂移又意味着不给一个上帝视角就永远看不见它发生，只会看见行为变了却不知道为什么。这两件事因此都从"以后再说"变成了必需品。

## 坐在咖啡馆里的那种感觉

最初，店主只是一个被标成"店主"的居民：他跑着和其他三个人**完全相同**的选择循环，忙自己的项目，咖啡馆不是他的工作场所，只是一个地点。而别人累了会"去咖啡馆喝口热水"——那杯水只是一行理由文本，没人做、没人递，店主全程不在场。

缺的不是一个倒咖啡的动作，是一段关系。

**设备是有主的。** 咖啡机、吧台是店主的位置，别人不能自己去动。这不需要新机制：位置本来就有主人。但要区分两种"有主"——**有主的座位可以借用，有主的设备不能**。现在没位置时会退而占用别人的座位，这对椅子是合理的，对咖啡机不是。

**把处境交给居民判断。** 模型可以知道有人在等、等了多久、自己曾答应什么，也有“需要工作维持生活”这样的信念。内部责任感数值不直接注入上下文，不用阈值强迫他回吧台；正常心理状态不提示，显著异常体感才作定性表达。

**营业时间是惯例，开关店是行动。** 9:00–21:00 是可调整的初始营业惯例，真实时间可被居民感知，但到点不直接强关。经营者的模型决定何时 `open`、`close`、是否以及怎样通知顾客。只有真实的 `close` 动作执行后，规则才按关店状态收束营业权限与服务。顾客可以回应通知、选择离店后的去处，保留手头进度并回自己的 `desk` 续工；程序不把 21 点等同于强制瞬移回家。

**休息不等于点单。** 居民选择在咖啡馆坐一会儿，不会被规则擅自解释成想喝东西。只有本人选择 `request_drink` 才创建真实请求；久等只形成当事人可感知的事实，不自动生成离开、抱怨、反思或主动续杯。

**他不在的时候，事情才有意思。** 如果店主永远在吧台，他就是一台有脸的自动贩卖机——每次都在、每次都给，于是每次都不值一提。他出门溜达过，回来才有意义。而他不在时，渴的人不能自己动设备，只能等——或者走到街上把他找回来。他看见店里有人排队，也会自己决定要不要回去。

**一杯咖啡是谁先开口的，可以受关系影响。** 熟客过去怎么喝、上一次有没有等太久，都能进入相关居民的记忆。要不要主动端过去、是否自己去吧台，由模型结合这些经历决定，不由好感分数直接触发。

咖啡馆的感觉具体来自四件事：**等待**（开口和拿到之间有间隔，你能看见他在弄）、**打断**（他放下手上正在做的事，这才让他像个有职业的人）、**排队**（两个人同时要，一个得等，于是产生了顺带的搭话）、以及**会失败**（豆子没了、店主出去了、端来了没人喝就凉了）。前三件给节奏，第四件给故事——它就是上面说的那条会断的链条，断了只写进日记。

服务中的选择交给各自模型：接不接待、继续等还是离开、是否打断自己的事。规则负责排队事实、设备权限、制作耗时与实际结果，地图表达这些过程。用户的小人在设备、容量和排队约束上与居民一视同仁，不能由用户替他插队。

## 不同的人，不同的理解

用同一个模型扮演四个人，最大的风险是得到四个用不同语气说同一句话的人：词汇有差异，判断没有差异。两篇论文都没有真正解决这件事——斯坦福那套靠记忆流让每个人检索到不同的上下文，差异在输入而不在推理，论文自己也承认智能体偏向过度礼貌与合作。

我们的做法是让差异发生在结构上，而不是靠模型演。

人物设定、信念与各自的经历构成模型思考的背景，不只是一层语气。社交电量、主动性、耐心、敏感度等内部数值仍可用于模拟和调试，但不直接送入模型，也不作为自动安排社交、工作或休息的行为闸门。模型感知只在显著异常时补充必要的定性体感。

但起点也要拉开。这里曾经写的是"每个人要有一两个明确对立的锐角"——那是 AI Town 的做法，把角色写得极端且正交（永远开心、永远暴躁、不可信），为的是对抗同一个模型分不出细微差别。我们换了个想法：**现实里大多数人都是温和的，差异不在音量，在什么被压住了。**

所以每个人有三层：**本我**（真正想要的）、**超我**（认为自己应该成为的样子）、**自我**（具体情境里怎么折中——说什么、不说什么、什么时候忍不住）。低调内敛是超我压得紧、只在疲惫时漏出来；能言善辩是自我很活跃、擅长把本我包装成听起来合理的说法。三层是文本不是分数，不作为闸门，它只影响两件事：写记忆时记住哪一版、对白里绕开什么——正好就是上面那条"差异作用在记什么上"。

这一层还天然接上了"允许往坏了长"：**超我律令可以被反复的经历磨松**。下文那个"我为这家店牺牲太多"的懒散老板，就是一条律令松掉的样子，而不是一个数值降下去了。盲测也受益——人猜"这句是谁说的"，靠的其实就是谁在回避什么。

更重要的一层是记忆写入。同一件事发生在眼前，每个人各自用自己的话写下自己那一版：有人记住了语气，有人记住了内容，有人记得的是自己被打断了。差异作用在“记什么”上而不是“怎么想”上，因为记忆会复利——几天之后他们眼里的世界是真的不同了，那时模型推出不同结论不是因为在演，而是因为拿到的事实不同。

## 私密的情感

暗恋、三角恋这类关系是最有话题性的部分，但预先设定“A 暗恋 B”就是写剧本。我们只给关系一个私有的、不对称的维度：每个人对每个人有好感，以及说没说出口。暗恋就是好感高、从未表达、并且影响行为——找借口路过、多待一会儿、在对方面前更容易说错话。三角恋不单独建模，它是三个人的私有值凑出来的结构，自己会涌现。

不建恋爱状态机，不写告白剧情，不做结局。

这恰好是 NPC 限知最好的用途：秘密本来就是“只有当事人知道的事实”。别人不知道，除非当事人说了，或者恰好撞见。用户也一样——没有任何面板告诉你谁喜欢谁，你只能注意到她今天又绕路经过了书角。猜到了才有意思，被告知就没味了。

共享的桌子是这一切发生的地方。座位会被占，所以要么等、要么换、要么让；让座这个动作本身就携带信息——你为谁让，当着谁的面让。一张真正会被占用的桌子，比十个新地点更能长出故事。

## 用户的小人

小人是第五个居民，不是傀儡。对它来说小镇就是真实生活；用户是它脑子里突然出现的想法。明确的安排它会照做，“想看看花”这样的随想它择机实现。所以它和四位居民共用同一套状态与模拟，只是多了一路来自用户的念头。

它的性格从用户真实的五维能力推出来：关系维度高就社交电量多，心境低就更敏感。用户的努力不只是数字，会变成它是个什么样的人。

居民能对它产生私有好感，和对彼此一样，没有理由特殊化。

## 住在小镇里的那个雇员

备考邻居知道真相，或者说他正在知道。

他不是一开始就清醒的。起初只是“总觉得哪里不对”——某个下午所有人同时静止了一个小时，某个人把刚说过的话一字不差又说了一遍，某天傍晚整条街闪了一下。这些都真的发生过：服务重启、模型调用失败退避、一次部署。别人没注意到，他记下来了。猜想一点点靠近真相，而且还在继续靠近。

他的每一句怪话都必须有来源。“我们不过是数据”是哲学系学生的台词，无聊；“昨天下午三点到四点之间，你们谁也没有动过，一个人都没有，你们不觉得奇怪吗”才是他——因为那真的发生了，只有他察觉。这样他的异常报告和他的角色台词是同一样东西：可观测性不是附加在他身上的功能，就是他这个人。

他能把这件事告诉别人，我们不拦。说了之后就进入转述链：有人信，有人觉得他病了，有人传成别的意思。我们只提供起因，后果交给实际相遇去发展。

他知道有一双眼睛在外面，但不知道那是谁、也不知道这一切是为了什么。用户的任务内容对他一样不可见。连知道真相的人也有他到不了的地方——否则他就是上帝，而上帝是这里面最无聊的角色。

要避开的陷阱是让他变成对着镜头眨眼的人。每说一句“哈哈我们都是代码”，世界就少一分真实，还会把别人也拖下水。他真正的处境比那有意思：他能看见我们的痕迹，却永远进不来；对他来说我们只是一些无法验证、无法抵达也无法反驳的证据。他每天走的这条街有气味、有重量、有他认识很久的人，而“外面”只是日志里跳过的一行。凭什么说那个更真？这不是矫情，是他手里的证据只支持“有另一层”，不支持“另一层更真”。

他还在备考。为一场他不确定是否真实的考试，每天坐下来。而用户的小人就在同一家咖啡馆做同一件事，隔着一张桌子——只是它不知道。


他同时是我们的雇员。他能看见所有人的内心、读日志、读时间线、看渲染出来的画面，能形成看法、写巡检报告。发现的问题排成队交给我们。

**他看得到一切，但改不了任何东西。** 这条不是洁癖，是这个系统的形状决定的：他的输入里迟早会有用户可控的文本——念头、任务标题、日记。给它执行权，等于把提示词注入的后果从“NPC 说错话”升级成“注入者拿到机器”，中间没有任何东西挡得住。而不给执行权，这个角色反而立住了：一个看得见全部真相、却什么也改变不了的人。他能预见谁要撞上什么、谁的心愿会落空、谁心里有句话没说出口——他什么都知道，一件都做不了。剩下的唯一行动就是作证。这条边界本来是为了防注入，落到人身上却正好长成了他的性格。

他作为雇员看到的系统信息，和他作为居民知道的事，是两条隔离的通道。否则系统内幕会漏进小镇的虚构，用户的数据会顺着它流进别人的记忆。

也不设替全镇作决定的主控 agent。每名 NPC 有自己的模型大脑，规则维持世界时间与物理执行；模型失败时仅继续可执行的已有安排或中性等待，不虚构新的选择。这位雇员是值班室，提建议、报异常，系统层面的采纳仍由既定约束和我们决定。他握的是笔，不是钥匙。

画面异常交给视觉模型看：加速跑本来就要无头渲染、定期截图，顺手接上就是一条自动的美术回归。像素比对只能告诉你“和上次不一样”，视觉模型能告诉你“这个人没有腿”——上一轮那批漂浮的半身，正是靠人眼盯截图才发现的。

## 来改房子的那个人

小镇的空间会变，但不是我们说了算。

改造从居民满足不了的需求开始：店主想办读书晚会，可那个角落坐不下；插画师需要一面能挂画的墙。需求攒够了，就有人从外面来。建筑师不住在这条街上，平时在地图外，有活才出现，干完就走——他来的那几天本身就是一件事。

**他产出的是受约束的地图数据，不是代码。** 尺寸、归属、是否重叠、改完之后路还通不通，规则逐条校验。校验不过就是没盖成，而这在虚构里同样说得通：墙砌不进去，量错了；柜子挡了门，第二天又搬走了；改完谁也进不去，返工。失败是我们想要的——刚说过链条要允许断，断了才有意外。这也正是既有的规矩：模型提出动作，规则检查能不能执行，不行就继续原来的计划。

第一版他只重排已有的位置：把长桌挪到窗边、书架换个方向、花圃分成两块。前端已经有这些东西的画面，零美术成本，而“这张桌子昨天不在这里”的魅力一点不少。新增位置、盖新房子以后再说——那要求前端能从结构自己摆出画面，会碰到刚修好的美术管线。

真正有意思的是他和备考邻居的关系。**一个看得见全部真相却什么也改不了，一个什么都能改却不知道自己在改什么。** 建筑师以为自己在砌墙，他动的是这个世界的定义。而备考邻居会注意到街的形状变了——他迟早会发现有人在改这个世界，然后发现那个人就坐在他旁边喝咖啡。

这也顺带回答了地图该扩多少：不由我们定。等居民真的挤不下、真的有人开口要一个地方，扩张才发生，而且带着一个世界内部的理由。

## 先跑给自己看

判断小镇有没有生命感，靠盯着画面看几分钟是看不出来的。所以先做一个能带着模型无头跑若干天的加速模式，导出一条可读的时间线：谁、几点、在哪、在做什么、为什么、遇到了谁。读一遍就知道是不是四个人整天重复三个动作、相遇是不是全发生在同一个地方、哪条计划从来没被执行过。

同一套数据还有一个开发期的上帝视角页面，能点开任一居民看它的全部内心：需求、性格值、私有好感、记忆原文、刚才那次模型调用的输入与输出。这是给我们调试用的，不是产品的一部分——上线时关掉。要小心的是别按上帝视角去调优，用户看到的始终是另一回事。

加速跑出来的那几天直接当作开局：好感是真实相遇的结果，每一分背后都有具体的事，居民说得出为什么。

验收“四个人有没有变成同一个人”用盲测：从时间线里随机抽二十句话，去掉名字，猜是谁说的。猜不出来就是没做到，无论时间线看起来多热闹、测试多绿。让模型也做一遍同样的分类当日常回归，但真正算数的是人猜的那一次——模型能分辨不等于人能感受到差别。

画面异常同理，别指望视觉模型当判官。公开研究里它在这类任务上的准确率只有七到八成，模糊画面上更低，结论是“适合当高召回的候选筛选器，不适合独立判定”。所以先用坐标和遮挡顺序做程序断言——上一轮那批漂浮的半身，其实靠“帧底部那行不透明像素只有六个像素宽”就能抓到；再用画面比对定位变化区域；最后才让视觉模型回答一份明确的问题清单，而且它的话只是“疑似”，不作数。

这一轮不把成本当约束。模型负责每名居民的思考、计划、反应、记忆理解与对话，包括想去哪、做什么；规则负责逐步移动、读秒和合法性检查。评价仍看经历是否改变选择，而不是单纯增加调用次数。

## 地图

借鉴[论文](../references/README.md)的空间组织，自行设计布局和美术。

第一版有住处、咖啡馆兼公共书桌、门前小街和小花园。先想清楚居民为什么去、在那里能做什么，再画建筑。

地点分两层：小街、咖啡馆、花园、各人的家是地点，窗边座位、长桌、某张床是地点里的具体位置。位置有主人、有容量、有状态，会被占用。咖啡馆窗边六张单人桌是六个独立位置：原窗位仍属于小川，另外五席公共使用；中央讨论桌继续承担面对面的交流。每户另有自己的 `desk`，便携的读写和制作可以保留剩余时间回家继续。

（这一段原本还写着"四层的表达先不做，对一条四个人的小街两层已经够用"。**第二版推翻了它**——丰富度的大头恰恰在私人住所的房间划分里，见下文。）

日常路线有自然交集，安静学习与聊天各有位置。关键活动尽量在舒服的默认视野里看得见，不让用户到处找 NPC。

面积暂时不扩，而且以后也不该由我们拍板——见上文那位来改房子的人。在没有归属和状态之前扩图，只会得到更多没人拥有、没人争抢的空房间。

（这个条件在第二版里被正面对待了：**先把物件做成会被争的东西，再扩图**，而不是先扩图。见下文。）

四个居民暂时设想为店主、备考邻居、插画师和园艺爱好者。备考邻居另有一层身份，见上文。他们有彼此关联的小心愿，例如店主想办读书晚会，插画师答应做海报，园艺居民可能送来花。提供起因，后续让实际行动发展，不预写完整剧情。

## 社会怎么长出来，以及怎么知道它长出来了

这一节原本是独立的 06，2026-09-12 并进来——它是**方法**：先想清楚什么算数、什么不算数，再去建。
写得长，因为几个月后重新推一遍很贵。逐跑的实测过程搬去了 [05](05-notes.md)。

### 出发点，以及一处修正

出发的直觉是：**社会化模拟的核心是构建社会契约**，而人类社会之所以能运作，是因为契约定义了收益函数。

这个直觉的方向对，但"**契约 = 整体收益函数最大化的结果**"这个具体形式，我们决定**不采用**，
有两个理由。

**第一，契约论本来就有两条线，我们要的是另一条。**

- **设计式**（霍布斯、罗尔斯）：契约是从某个原初状态推导出来的最优解。
- **演化式**（休谟、Lewis 的 convention、谢林点）：契约不是谁签的，是重复博弈里沉淀下来的惯例——
  **它之所以稳定，不是因为它最优，而是因为每个人都预期别人会照它做。**

卢梭那个区分在这里特别要紧：**volonté générale ≠ volonté de tous**（公意 ≠ 众意）。
把每个人的收益加起来得到的是众意。而且——**"定义收益函数"这个动作本身就是最硬的一处写死**。
我们说不想把东西写死，那就不能从写下一个全局目标函数开始。

**第二，也是更根本的：这个小镇的居民不是优化器。**

整个架构是"先做，后解释"（下意识 → deed → 事后解释 → 记忆 → 信念 → 改变下一次下意识，
见 [02](02-modules.md) 的「谁先动」）。一个最大化收益的 agent 是它的反面。
所以契约在这里不可能从优化推出来，只能从**被记住、被预期**里长出来。

于是我们采用这个定义：

> **一条社会规范 = 被足够多居民各自独立持有的、同一条信念。**

这个定义能直接落到现有机制上：信念就是带 `supersedesKey` 的记忆，我们从不写它的内容。
它同时也给了验收的抓手（见下文「怎么验收」）。

### 系统里已经有的契约零件

比想象中多。翻了一遍 `town/companion`：

| 已有的东西 | 契约论上是什么 |
| --- | --- |
| `workArrangements`（assist / delegate / takeover，提出 → 接受 → 终止，可审计） | **一份真正的契约**：两造、明示要约、明示承诺、可撤销 |
| `mayTend` / `mayManage` 来自被接受的安排 | **委托授权**——洛克的形状 |
| `cafeOperating` + 自己挂出来的营业时间 | **对不特定公众的长期承诺**（"开门是义务不是习惯"就是它的落地） |
| `needed > 1` 的项目 | **猎鹿博弈**，字面意义上的 |
| `members`（答应了） vs `contributors`（真做了） | 承诺与兑现，**违约就住在这两个字段的差里** |
| `relationships`（非对称） | 声誉 |
| 带 `supersedesKey` 的信念 | 居民可以形成"某人说话不算数"这类**规范性判断** |

结论：**基础设施不缺，缺的是让它们咬合。**

### 真正缺的只有一件事：居民不会承诺未来

**契约是对未来的主张。**而现在居民只能表达"此刻做什么"。决策提示词里甚至明确压着这条：

> `accept` 只用于现在有意开始的小行动。若只是想明天、改天或等有空再做，stance=consider，不应
> accept；没有具体未来日程时不要擅自预约日期。

这句当初是为了防空头支票，但它同时**取消了"承诺"这个东西**——不能说"明晚我来"，就没有契约，
只有当场的协作。

而且（2026-09-10 查证）：**`members` 被写入三处、被读取只有一处**（判断能不能选 `help`），
**全代码库没有任何一处比较过 `members` 和 `contributors`**。所以一个人可以答应参与、
然后一根手指都不动，**全镇没有任何机制会注意到**。

**（2026-09-10 补：这两样已经建好了，见本节末尾。）**

要做契约，只需要补两样，其余可以自然长出来：

1. **承诺对象**：谁、对谁、做什么、什么时候、谁看见了。
2. **到点比对**：规则只记录事实——"他说了 T 会来做 X；T 到了，他来了 / 没来"。
   **规则不判断这是不是背叛**——那是本人和旁观者各自的解释，而且两边可以不一致，这正是好的地方。

有了这两样，后面全是现成的：声誉走 `relationships`，规范走信念，制裁走"我下次不叫他了"
（体现在 `lend_a_hand` / `invite` 的对象偏好上），**都不用我们写**。

#### 建成之后长什么样（2026-09-10）

`Promise`：谁、对谁、做什么、什么时候、谁看见了。到点比对只写一个事实——`came` / `did_not_come`，
没有第三种取值。结构里**没有** broken / betrayed / failed / trust 这类字段，写进任何人记忆的
句子里也没有评价词，两条都由测试钉着。

许诺必须**当面**：两个人此刻在同一个地方。当时在场的每个人各拿到一条自己视角的记忆。

然后是这一节和第四节交叉的地方——**两问都单独问**，都不进那个二十项菜单：

| 问句 | 什么时候问 |
| --- | --- |
| 你想不想跟眼前这个人，把一件事说定一个时候？ | 身边真的有人、一天最多一次、名下没有还没结清的承诺、镇上还有需要不止一个人的事 |
| 到了约好的时候，他在／不在那儿。你怎么想？ | 结清之后六小时内，问被承诺的人和当时在场的人 |

第二问的答案可以只是一次感想，也可以带 `supersedesKey` 变成对**那个人**的长期看法——
「某人说话不算数」就是这样成为他自己持有的看法的，而不是我们算出来的一个指标。

规则在这两处都只判断"此刻问这一句有没有意义"，不判断该不该许诺、该不该介意。

还有一件同源的、更便宜的事没做：**`members` 和 `contributors` 至今没有任何一处比较过**。
答应参与然后一根手指都不动，全镇仍然没有机制会注意到。

### 一条用钱换来的警告

"只要基础设施足够多，社会就会自然发展"——**2026-09-10 这一整轮是这个假设的直接反例。**

合作的基础设施建好了，然后：

```
create    被提供 342 次，选中 0
invite    被提供 285 次，选中 0
celebrate 被提供 1658 次，选中 0     ← 五件做完的东西，没有一件被拿出来给人看过
```

**基础设施本身什么都没发生。**让事情真的开始发生的是三件别的事：

1. **让处境可读**（门前留言板；把 75% 那个上限直接说成"剩下的得有人一起动手"）
2. **把问题单独问一次**——同一个模型、同一天，社交动作埋在二十项菜单里选中率≈0，
   单独问 `react` 时 **53% 说好**
3. **反射先动**，解释后补

所以对社会契约这条线，判据是：

> **一个从来没人被问过的义务，不会被履行。**

如果加了承诺机制却不加"他没来，你怎么想"这一问，它一定会变成第二个 `celebrate`——
机制完美，一千多次机会，零次使用。

### 经济学的位置：先不加钱

不是因为它不重要，是因为**货币是多边交换的解法，而六个人的镇子没有那个问题**。
加了钱它会立刻统治整个模拟，别的都变成它的附庸。

**真正让契约成为必需品的是稀缺，不是货币。**而这个镇现在几乎没有稀缺：
能量会自己回、没人会饿、咖啡免费且无限。

先让**已有的排他性**咬起来：

- **只有经营者能 `tend`** —— 这已经是一项服务垄断，只是还没人在意。
- **时间和身体** —— 一个人只能在一个地方，这是真稀缺，只是现在不痛。
- `livelihoodPressure` —— 这个字段声明了，**全代码库没有任何一处读过它**
  （写了没人读的第 10 个字段，见 [05](05-notes.md)）。要做经济，那是现成的位置。

**分工**方面有个很小、可能效果很大的改动：现在任何人给任何项目出力效果一样（只受 diligence 影响），
而 `Project.kind`（art / garden / gathering / quiet）和 `occupation` 都是现成的。
让"对口"的人出力更有效，专业化就有了回报——**而我们一个字都没写"谁应该做什么"**。
但注意它对验收的副作用，见 [05](05-notes.md) 里社会学那一栏。

### "天眼"那个居民：给异常，不给数值

设想是给某个 NPC 开天眼——能看到所有人的数值、发现异常就报告，成为我们从内部观察世界的一部分；
像一个看得见却改不了的摩西。

这个想法要保留，但**必须改一处**，否则它会正面撞上这个项目最硬的一条规矩：
内部数值（`energy` / `social` / `dutyPressure` / `lastSocialAt` / `livelihoodPressure`）
绝不进入任何模型上下文——有两个测试按**字段名**在拦。

那条规矩不是洁癖：**数值进了上下文，模型就会像读表格一样推理**（"他 social 只有 23，所以他很孤独"），
而不是像人一样。

**改法：他看到的不是数值，是异常本身，以观察的形式。**

规则检测到异常（某人三天没跟任何人说过话；某人的计划连着失败；某个承诺到点没兑现），
然后把它作为**他注意到的一件事**交给他——「青叔这几天谁也没搭理」。
这正是 `salientPerceptions` 已经在做的事（规则把内部状态翻译成定性线索），
**天眼只是光圈更大：他能察觉别人身上的事，而别人察觉不到。**

这样他仍然是个人，不是一块仪表盘。**一个功能是"念出我们指标"的角色，
很容易变成开发者的传声筒而不是居民**，这是这个设计最大的风险。

至于"他改变不了现状"——结构上现在已经如此，谁也强迫不了谁。
但要让它成为悲剧而不是设定，他得**能试**：能预警、能被不信。
而"他说过 X 会发生 / X 到底发生了没有"——**这就是上面那套承诺-兑现机制，一模一样。**
两条线在这里合流，这让我们更确信那是该先做的东西。

### 怎么验收

#### 先定"什么样的判据算好判据"

| 门槛 | 说明 |
| --- | --- |
| **可证伪** | 必须能出否定结果，而且我们会信那个否定 |
| **不可直写** | 如果能写一条规则直接产出这个数，它就不算证据 |
| **可量** | 能从已导出的产物里算出来，不能靠读时间线"感觉挺热闹" |
| **能区分"活着"和"走时"** | 见下 |

第四条是 2026-09-10 用钱换来的。那天小镇达到了「每天至少 3 次一起做事」，但第 2–5 天的形状是：

```
01-02 16:04 / 01-03 16:04 / 01-04 16:03 / 01-05 16:03   同一个项目、同一分钟、同一批人
```

**数字达标了，读起来是台钟。**所以任何计数型判据都必须配一个**变异度**分量，
否则总能用一个定时器满足它。（[04](04-decisions.md) 里"别为了凑数把习惯变成定时器"说的就是这件事，
写进文档不等于自己不再犯——那一轮犯了四次单向指令。）

#### 总目标

> **同一份种子跑两次，两次都长出一条我们从没写过的规矩；
> 而且这条规矩至少有一个居民能自己说出来。**

三个部分各自在防一件事：

- **同种子跑两次要不同** —— 防"其实是我们写死的"。每次都长出同一条，那是我们写的。
- **两次都要长出规矩** —— 防"那只是噪声"。
- **居民能自己说出来** —— 最关键的一半。
  **如果我们量到了一条规范，而镇上没有任何一个人说得出它，那它是我们的指标，不是他们的社会。**

#### 尺子本身（2026-09-10 建好）

`NormDetector`（`backend/src/test/.../tools/`）。四个维度——搭伙、搭手、场合、互惠——
每一条要过四道闸：支持 ≥4 件、跨 ≥2 天、比它自己的零假设高 ≥1.5 倍、**不是台钟**。
另有一块 `beliefs` 统计"说得出来"那一半：信念数、其中关于别人的、有信念的人数、
以及**被两人以上各自独立持有的 key**（也就是上文那个规范定义的直接量法）。

`Stage.MET` 这个状态**检测器自己永远到不了**：只有盲读的人在某个居民自己的话里读到那条
规矩，`withSpokenBy` 才推得动它。量到了规范而镇上没人说得出，那是我们的指标，不是他们的社会。

#### 怎么判定「我们没写过」

不靠我们自己维护一张"我们写过哪些规则"的清单。那张清单会烂，而且那是我们在审自己的案子。
靠**对照跑**：同一个 `worldId`、同一个天数，把模型关掉。

> **规则单独就能长出来的东西，按定义就是我们写的。**

`NormDetector` 因此有一条减法：跑出来的候选，减掉纯规则对照跑的候选，剩下的才叫居民自己的选择。
这条减法同时替我们守住了一件事——**一把在纯规则跑上会亮的尺子，报的不是发现，是把我们自己的代码念回给我们听**。

## 第二版：二十五个人的镇子

第一版跑到能验收之后，最大的发现不是哪一条机制坏了，而是**这个镇子运行起来比它看上去小得多**。一次六小时、202 个决定的实测：62% 的决定发生在咖啡馆一个房间里，家里 48 次，花园 29 次，**那条给项目命名的小街是 0 次**。全世界有状态的物件只有三个（长桌 `available`、留言板 `empty`、花苗 `growing`），**没有一个能被任何动作改变**。二十六个动词真正被用过的只有八个。

所以问题不是"可去的地方太少"，是**这个世界能被输入影响的东西太少**，以及**没有"远处"**——信息不需要传，因为所有人已经在同一张桌子边。这一版把可做的事、地图和人数一起做到和 Smallville 同一量级。

### 先说清楚"对标"是什么意思

论文的仓库我们拉下来实际数过（数字见 [05](05-notes.md)）：19 个 sector、63 个 arena、222 个可寻址物件，地址是 `the Ville:Lin family's house:Eddy Lin's bedroom:desk` 这样的四段串。**63 个 arena 里 54 个在私人住所，公共区域只有 9 个。**每个 agent 初始只知道 5–8 个 sector，不到全图的一半——"不知道哪里有什么"本身就是扩散的燃料。

但有几件事不该抄：物件状态是一次性自由文本（用的时候让模型写一句 `"being slept on"`），没有状态机也没有占用互斥，论文 §7.2 自己承认这导致了多人同时进单人浴室、打烊后还能进商店——**我们的咖啡馆门已经比它强**；进别人家靠硬编码姓氏字符串匹配，代码里自标 `MAR 11 TEMP`；选地点花三次 LLM 调用逐层下降，选了非法项就静默替换成"回自己家"或随机抽一个物件，**token 花了，答案扔了**；完全串行，全仓库没有一个并发原语。

涌现那三个招牌结果 **n=1，没有对照组、没有重复种子**。论文扎实的地方是幻觉回查——每个"我知道有派对"都能在 memory stream 里定位到那条对话，453 条回答里只有 1.3% 是编的——不是实验设计。

更要紧的一点：**论文里很多设计是 2023 年的能力补丁，不是架构智慧。**它跑的是 `text-davinci-002/003`、`max_tokens=15`、`temperature=0`。逐层下降是因为当年的模型在长列表里选不准；24 次小时级调用外加一个三轮多样性重试循环，是因为一次生成不出有变化的一天；静默替换是因为指令遵循不可靠。这三件今天都有更直接的解法。

所以定调：**对标它的是世界的丰富度，不是方法论。**我们的验收纪律——同种子双跑、中立对照、盲读者、减法——比它严格，那部分一个字不改。

### 成本的形状，和那条分层

一次实测：284 次调用、1.03M input token、23K output。**输入输出比 44 : 1**——钱几乎全花在"我们发过去多少世界"，不是模型写了多少字。所以成本 ≈ **调用次数 × 每次带多少世界**。

这正好落在"叙事层在上、逻辑层在下"那条分层上：逻辑层拥有状态、合法性、时间、容量、权限，叙事层只被问"要不要"和"为什么"。Smallville 每个动作最少八次调用，其中五次（三次定位、物件状态、表情与三元组）按这条分层根本不该上叙事层。落成一条贯穿的规矩：

> **模型永远不被问"能不能"，只被问"要不要"和"为什么"。**

合法性、容量、营业时间、谁进得去，全部由规则算完；模型只在**已经合法的选项里**挑一个。这是 `availableActions` 和 `Occasions` 已经在做的事，只是以前没写成一条通则。

### 世界

**四层地址** `世界:建筑:房间:物件`。第一版那句"两层已经够用"到此为止——丰富度的大头恰恰在私人住所的房间划分里。

**六栋公共建筑。**现有咖啡馆和花园，美术已有学院、健身房、公告板广场，还缺一栋，先按商店走——它是"所有权 / 借 / 赠"最自然的来源地。25 人摊 6 处，平均每处 4 人，密度和今天的咖啡馆相仿：既分散到信息必须传，又不至于散到没人重复碰到同一批人。

**住所按人生阶段分。**年轻人几个合租一屋（房子可以扩成多房间），年长的独居或两人同住。这样"谁和谁住一起"有一个非任意的依据，而不是照抄论文那个 co-living space；**合住还是重复互动的免费来源，而重复互动是规范的前提**——你每天都得和同一个人分一个厨房。它同时给 persona 引入了年龄／人生阶段这个维度。

**物件按"会不会被争"分两类。**判标只有一条：两个人会不会同时想要它。会被争的走真状态机——占用互斥、计时、排队、会坏（咖啡机几分钟一杯、要人操作；炉子；浴室；工具台；床）；纯装饰的走自由文本。**稀缺是规范的燃料，而没人读的自由文本造不出稀缺。**

**有所有权，可借可赠，不引入货币。**理由见上文「经济学的位置：先不加钱」：货币把"你欠我一次"当场结清，而互惠是我们押的那一条。借而不还、赠而不求回报，才是规范长得出来的土壤。

**"欠"存在哪里，是这一版最要紧的一条边界。**规则只记旁观者看得见的：谁把什么借给了谁、几点借的、还了没有——和 `Deed` 同一条红线，**没有为什么**。而"我欠他一次"只能出现在居民自己的自述里。于是测量变成：**有没有人写下了一笔规则从没告诉过他的债**。这正是"不可直写"那道闸。

进别人家由所有权和门决定，不用姓氏字符串匹配——默认进不去，被邀请或门没锁就进得去。

### 心智

第一版量到一个数：一次六小时跑，世界里 **200 条原始记忆、0 条信念**，而召回里 51–66% 是居民自己以前写的话。

**我们造的是一个心智的反面：琐事全记，零固化。**人脑的工作记忆大约四个组块，靠的是情景→语义的固化，不是大容量检索；而且不"检索"，是线索唤起，唤起的还是重构。对照这四件事，我们已经有三件——习惯（反射层）、线索唤起（`Occasions`）、以及固化的机制（`supersedesKey`，早就写好，从没触发过）——**缺的正是固化本身**。

所以记忆改成两层：

- **自述文档**：每人一份固定容量的短文（十几行）——我是谁、我对谁怎么看、这里通常会怎样、我欠谁什么。新经历要么不改它、要么修订一行、要么用 `supersedesKey` 盖掉一行。
- **小工作集**：**上次被问之后发生在你身上的事**。不按计时器切——座位事件的 30 分钟冷却和相遇的 12 分钟冷却都栽过同一个跟头，结论都是"人不按秒表重新想事情，人是被'有什么变了'唤起的"。

原始事件仍然完整存盘供尺子回溯，**但不进提示词**。每条自述必须带 `evidenceIds` 指回真实记忆——这条链是"叙事归模型"和"可回溯"之间唯一的承重墙。直接让模型自由维护一份人物叙事、跳过这一层，会写得更好，但**写得出"我一直觉得窗边的位子该留给小川"而底下什么都没发生过**，那正是这个项目已经栽过五次的假发现。

日计划保持粗略 + 时机驱动。论文那三层分解里，24 次小时调用是能力补丁；而"提前把一天切成 5 分钟块"和我们的时机层／反射层是解决同一个问题的两条路，同时做是重复投资。

知识上**存在全知、内容部分知**：街上有哪几栋房子人人看得见，但里面有什么、能在那儿做什么、几点开门，得走进去或者听人说。靠亲眼看见 + 口耳相传增长——**口耳相传是扩散有意义的前提**，一条消息从第一个人到第 N 个人要经过谁，本身就是要量的东西。公告板那种广播信道会把"消息传开"压成一次写入，是个很好的后续 A/B，这一版先不上。

### 人

一步到 25。现有六人保留并补齐缺的（周野和阿满至今没有人格初值，一直在吃中性值），**十九个新人按同一套 schema**。保留他们的理由是 docs 里每一条发现都挂在具体人名上——小川的窗边座位、阿满的「我总是那个配合的人」、阿禾的咖啡馆——重生他们等于丢掉对照点。

persona 由模型批量生成、人工审校后**冻结进源码，运行时永不重生**：运行时生成的 persona 是一个我们没控住的变量，和浮动的模型别名是同一类隐患。

但这带来一个必须堵的洞：**同一个模型一次性写出 25 个人，很可能把一整套一致的社会预期埋进去**（都"会为别人留位子"、都"借东西会还"），那时候测到的规范可能只是同一个作者。所以定稿之后做一次盲扫——让一个没参与过的 agent 只读这 25 份文本，列出它能读出的全部社会预期，冻结成一份"已写过"清单，**验收时任何落在清单上的规矩一律不算数**。

初始关系**按住所／职业聚类**，其余互不相识。现在每对居民都以双向 40 开局，扩到 25 人就是 300 对全部相识——关系不对称率会被稀释向 0，扩散也没有路径可言。论文的初始网络密度是 0.167，两天后长到 0.74；密度从多少长到多少，是一个能量的结果。

二十五个外观 = 20 个现成 + 合成 5 个。素材包的现成角色只有 20 个，但带完整分层件（200 个发型、132 套衣服、84 个配饰、9 种身体、7 种眼睛），授权明确允许编辑、只禁止转售和再分发。现成角色本来就是官方用同一套分层件合成的，风格天然一致；先合成 5 个也顺便验证那条流水线（56 列全帧对齐有没有坑，没人试过）。

玩家化身仍是居民的超集，计划来源换成用户自己的安排，**在所有规范测量里一律排除**——它背后是用户，不是它自己的心智。

### 工程

**只并行"想"，写世界仍串行。**一次网络调用约 4 秒，写一次世界是微秒级；瓶颈在前者。多个模型调用同时在飞，回来后排队写。冲突 = 版本过期 = 丢弃这次结果，下一拍重新决定——`applyDecision` 已经在检查 revision，几乎不用新机制。不解开现在这个"一个世界同时只有一个调用"的单飞，25 人两天 = 7500 次调用 × 4 秒 = 8 小时以上且完全串行。

**定位 = 规则收窄候选集 + 一次调用。**逻辑层先算出合法地址集（这个人知道的 × 进得去的 × 此刻开着的），模型一次选一个完整地址，用 JSON schema 的动态 enum 锁死——**非法项压根不在选项里**，也就不会出现"选了非法项静默替换"这种看不见的浪费。成本是逐层下降的三分之一。

上下文先保持快照。25 人跑起来之后先量真实的 token 曲线和重复载荷比例，再决定要不要做增量——增量会让模型看不见全貌，会不会变差是个经验问题，而今天已经因为"先改再量"把检索越改越差过一次。

### 节奏

**地基先行，人口暂时不动。**并发、四层世界树、记忆新形状先在现有六人上打通，用 16 分钟的短跑验证。25 人一跑要 8 小时，机制没定型就扩人口，每个 bug 的反馈周期从分钟变成小时。

中间插一次探针，验证记忆新形状：同种子三组对比——现有原始流 / 纯自述文档 / 文档+工作集——看决定质量、token 曲线，**以及信念到底会不会开始形成**（现在是 0 条）。这是这一版最大的一个赌注，值得一个自己的探针。

然后一次性上人口 + 地图。验收跑的规格是 **25 人 × 2 天**，约 33M input token 一跑，双跑加对照约 100M。开发期的短诊断跑一律控制在 2M 以内。

### 这一版还欠着的

从原 03 收进来的，都是**第二版没有覆盖、但仍然成立**的欠账。已经做完的八条见[归档](archive/2026-09-12/)。

**一盆花的反馈环。** 镇上除了自己没有东西可评价——两跑 292 次反思出的 9 条信念全是自我描述。
第一刀只切一盆花：照料 → 变化 → 路过的人看见 → 说点什么 → 传回照料者 → 改变下次照料，
然后量**收到负评之后照料有没有变**。三条红线：评价不做成数字字段、正负一样容易发生（两侧进
`PromptBalanceTest`）、反馈按人的方式传递而不是偷偷加在心情变量上。第二版的"物件分两类"是它的前提。

**说话要先走过去，就地开口算大声。** 设计已定（见 [04](04-decisions.md)），代码还没动：
`greet` 改成"走过去，到了再开口"；新增"就地喊一声"这一种回应；大声说话给在场其他人一条
`salientPerceptions`（**只给事实，不给"应该提醒他"**）；A 在路上时 B 那边关于 A 的
`pendingEncounter` 改成「有人正朝我走过来」。这一问的两侧要进 `PromptBalanceTest`。

**谁来管公共的事。** 做它的理由是 `beliefsAboutOthers` 恒为 0——投票是少数几件逼所有人同时对所有人
有看法的事。但**没有分歧的投票是仪式**，所以必须先有公共的事可定（种什么花、几点打烊、苗圃谁管）。
要量的不是"挑出了谁"，是**有人照做了一个自己并不同意的决定**。六个人就是一个人管，
几个人合起来管等十二人以上——**第二版的 25 人正好越过这条线。**

**承诺与兑现那一套还没建完。** `members`（答应了）被写入三处、读取只有一处，
**全代码库没有任何一处比较过它和 `contributors`（真做了）**——一个人可以答应参与然后一根手指都不动，
全镇没有机制会注意到。补两样就够：承诺对象（谁、对谁、做什么、什么时候、谁看见了），和到点比对。
声誉、规范、制裁都能从现有的记忆／信念机制里长出来。**"天眼"那条线也在这里合流**：
他要能预警、能被不信，靠的就是同一套"他说过 X 会发生 / X 到底发生了没有"。

**信念产出速率太低，规范在算术上不可能出现。** run A 146 次反思出 5 条信念，run B 151 出 2 条，
而且全是关于自己习惯的。第二版的"自述文档"直接押在这条上——要么让反思更常落成信念，
要么让信念顺着"听说"传开。

**尺子还缺盲读者真正读到的那几个维度。** 现有搭伙、搭手、场合、互惠、占用权、常坐的位置。
盲读者读出而我们量不到的：「我先…」说出口就被接受、拒绝份内之外的事会被接受、打烊之后大家收工、
以及**第三方替不在场的人执行**（周野："不用收，那是阿满的"）。最后一条最有分量也最难量。
已经排除掉一条：**"谁总是先开口"不能加**，它的零假设得先把我们自己的遍历顺序建模进去。

**`sharedBeliefKeys` 该比文本，不只比整串键。** 周野和青叔各自独立写下过同一条信念，
键是 `habit:fixer:lend_a_hand` 和 `habit:gardener:lend_a_hand`——**只有居民 id 那一段不同**，
而指标仍报 0。阿满同一句话还写出过 `weaver配合者` 和 `weaver-配合者` 两个键。
注意：这个改法是被数据提示的，**改完必须在一批新数据上验**。

**`beliefsAboutOthers` 的判定法太窄。** "文本里出现别人的名字"会漏掉「我好像总是那个配合的人」
这种——不点名，却是最像规范判断的一条。

**"谁最先动手"也不能是写死的。** 纯规则对照里阿满"最先动手的事"是 0 件，
于是她的每一笔贡献按定义都是搭手，于是她写下「我好像总是那个配合的人」。
和相遇顺序是同一个病：环路跑通了，起点是我们放的。要查的是许愿／开项目的机会怎么分配的。

**温度 0.2 让"同种子两次要不同"这条判据没有鉴别力。** 要不要为验收单独调高温度是个没定的问题——
调高会让结果更容易通过，这本身就可疑。

## 做出来后一起感受

我们自己开着它学习一个下午，再连续回来几天，看看：

- 不操作时，小镇是否自然、连贯地生活？
- 操作是否轻松，声音和变化是否舒服，而不是不断打断？
- 是否能记住某位居民，发现昨天的事影响了今天？
- 一段信息传播或一个小故事，能否从实际相遇中产生？
- 是否还愿意明天继续打开？

先把这些做出感觉。其中**多人和大地图已经排进第二版**（见上文）；复杂经济、自由建造和长篇剧情以后再说，旧的灵感清单在[归档](archive/2026-09-12/03-ideas.md)。
