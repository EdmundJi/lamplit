# 「成为更好的自己」完整 MVP 系统设计

版本：1.0  
日期：2026-07-31  
状态：已确认，待实施计划

## 1. 目标与设计依据

本项目建设一套面向 18 岁以上用户的游戏化个人成长 Web 应用。产品以「4 周目标 - 周计划 - 弹性执行 - 个人反馈 - 周复盘」为核心闭环，覆盖学生、健身、职场和情绪支持四个场景包，并使用 Qwen 提供任务建议、一般性对话和复盘草稿。

实现以用户提供的 v2.0 文档包为需求基线。发生冲突时按以下顺序处理：

1. `00-修订说明与文档索引.md` 与 `文档一致性矩阵.md` 的唯一口径。
2. `软件需求规格说明书_final.docx` 的功能和验收需求。
3. `系统架构设计文档_final.docx` 的架构、安全和部署约束。
4. API、数据库、模块、安全、指标和启动指南中的详细契约。

## 2. 交付范围

### 2.1 用户端

- 注册、登录、刷新、退出、全部设备退出、忘记密码、重置密码和修改密码。
- 18+ 校验，以及用户协议、隐私政策和 AI 服务说明的版本化独立同意。
- 场景选择、每日可用时间、每周频次、难度、IANA 时区、提醒、安静时段、AI 保留期和 AI 记忆设置。
- 五个系统成长维度和用户自定义维度；已使用维度只能归档。
- 14-84 天目标，默认 28 天；同一用户最多 3 个活跃目标。
- 周计划、一次性任务、重复任务、计划实例和任务事件。
- `PLANNED`、`IN_PROGRESS`、`DONE`、`PARTIAL`、`DEFERRED`、`SKIPPED`、`EXPIRED`、`CANCELLED` 状态，以及最近事件撤销。
- 实际时长、完成比例、主观难度、感受、备注和可选附件。
- 个人周计划兑现率、有效行动、恢复次数、个人最佳和维度趋势。
- Qwen SSE 对话、结构化任务建议、建议编辑与采纳、周复盘草稿。
- AI 记忆逐条确认、查看和删除；AI 会话单条或全部删除。
- 通知渠道偏好、安静时段、每日上限和一键暂停。
- JSON/CSV 数据导出、短期下载、账号注销、7 天冷静期和撤销。

### 2.2 管理端

- 内容运营、安全运营和管理员的角色及权限点隔离。
- 管理员 TOTP 多因素认证。
- 任务模板、提示词版本、知识来源的创建、送审、发布、停用和回滚。
- 脱敏 AI 安全事件列表、审核与升级。
- 审计日志查询和敏感正文访问审计。
- 产品、AI 和安全聚合指标看板，不展示敏感正文。

### 2.3 明确不做

- 公开排行榜、陌生人社交、社区 Feed、付费商城、虚拟背包和复杂皮肤。
- 未成年人服务、医疗诊断、治疗、处方、心理治疗或危机干预替代。
- 原生移动端、模型微调、WebSocket、微服务拆分和 Kubernetes。
- 自动抓取开放网络内容进入知识库。
- 用连续天数惩罚用户，或因跳过、延期和缩小任务扣除历史经验。

## 3. 设计立场

产品界面采用安静、务实、低压力的工作台风格。视觉系统使用暖白背景、深绿色主色、深灰正文和少量琥珀/红色状态色，不使用紫蓝渐变、装饰光斑、超大圆角卡片或营销式首屏。

信息密度以重复使用效率为优先。任务列表使用分隔线和稳定尺寸控件，不用卡片堆叠替代层级。经验值只作为个人历史反馈，不描述为能力、人格或心理状态测量。

所有核心页面覆盖加载、空、错误、超时、离线恢复和权限不足状态，并满足 WCAG 2.2 AA 的对比度、键盘操作、焦点指示、表单标签和减少动画偏好。

## 4. 系统架构

项目采用单仓库结构：

```text
growth-platform/
  frontend/            Vue 3 前端
  backend/             Spring Boot 3 模块化单体
  deploy/              Docker Compose 与 Nginx
  docs/                设计、计划和运行文档
  .env.example         无真实凭据的变量示例
  README.md            本地启动和验收入口
```

技术栈：

- 前端：Vue 3、TypeScript、Vite、Vue Router、Pinia、ECharts、Vitest、Playwright。
- 后端：Java 21、Spring Boot 3、Spring MVC、Spring Security、Bean Validation、Spring Data JPA、Flyway、Actuator、Micrometer。
- 数据：MySQL 8 为权威数据源；Redis 7 只用于限流、短期缓存、幂等快速命中和撤销列表。
- AI：Qwen OpenAI 兼容接口，通过 `QwenProvider` 适配层调用；模型名来自环境变量。
- 文件：MinIO 作为本地 S3 兼容对象存储，生产环境可切换托管 S3。
- 入口：Nginx 提供前端静态资源、`/api/v1` 反向代理、SSE 和安全响应头。

浏览器只与 `/api/v1` 交互。业务写入在 Spring Boot 内完成事务；MySQL 保存业务事实；提交后通过 Outbox 刷新缓存、发送无敏感正文埋点并调度异步任务。Redis 故障不能阻止目标、计划和任务事件写入。

## 5. 后端模块边界

- `auth`：密码、Cookie 会话、刷新轮换、CSRF、密码重置和管理员 MFA。
- `identity`：资料、年龄、同意、偏好、时区、通知和 AI 记忆开关。
- `goal`：维度、目标、周计划、任务定义、重复规则和模板引用。
- `execution`：计划实例、任务事件、状态机、幂等、经验、延期和撤销。
- `insight`：个人指标、趋势、个人最佳、恢复和周复盘确定性统计。
- `ai`：会话、消息、结构化建议、建议采纳、周复盘、SSE 和 Token 预算。
- `safety`：L0-L3 分类、场景规则、专业边界、危机响应和安全事件。
- `privacy`：导出、对话删除、保留期、注销冷静期和删除编排。
- `admin`：内容发布、知识来源、提示词版本、审核和审计查询。
- `shared`：统一响应、请求标识、时间、ULID、Outbox、对象存储和可观测性基础能力。

模块只能通过公开应用服务或领域事件协作，不跨模块调用 Repository。资源查询同时限定当前用户 ID；不存在和不属于当前用户的资源统一返回 404。

## 6. 前端信息架构

### 6.1 用户端导航

- `今日`：默认首屏，展示本周进度、今日任务、快速记录、延期和跳过。
- `目标`：4 周目标、周计划、重复任务、模板和 AI 建议采纳。
- `洞察`：个人趋势、日历、恢复、个人最佳和周复盘。
- `AI 助手`：SSE 对话、建议确认、AI 标识、安全状态和会话历史。
- `设置`：资料、通知、记忆、保留期、导出、对话删除和注销。

桌面端使用左侧导航和内容工作区；移动端使用五项底部导航。管理端使用独立受保护布局，避免普通用户界面暴露管理入口。

### 6.2 核心交互

今日任务行内提供记录、延期和跳过；记录面板支持完成、部分完成、实际时长、完成比例、难度、感受和备注。危险或不可逆操作使用二次确认；成功后显示结果和撤销入口。

AI 建议先以可编辑清单展示。用户明确勾选并确认后才创建任务。AI 不可用时页面保留手动创建入口，已存在目标、任务和历史复盘仍可使用。

L3 状态切换为专用安全页面，隐藏经验、成就、任务建议和普通对话输入，只展示经审核的本地紧急服务、可信任联系人和专业资源入口。

## 7. 认证与授权

- Access Token 使用短期 JWT，30 分钟，存入 `HttpOnly`、`SameSite=Lax` Cookie。
- Refresh Token 使用高熵随机值，7 天，仅通过受限路径 Cookie 传输；数据库只保存 SHA-256 哈希。
- Refresh 每次使用后轮换。旧令牌重放会撤销同一 token family 的全部会话。
- CSRF Token 使用非 HttpOnly Cookie，并在所有写请求的 `X-CSRF-Token` 头中回传。
- 本地 HTTP 环境关闭 Cookie `Secure`，测试和生产 HTTPS 环境强制开启。
- 用户密码使用 Argon2id；密码重置令牌只保存哈希并设置短期有效期和单次使用约束。
- 管理员在密码登录后必须完成 TOTP 验证，发布和敏感审核操作再次校验 MFA 状态及权限点。

真实 Qwen Key、数据库密码、对象存储密钥和 TOTP 种子只写入被忽略的 `.env.local` 或测试环境 Secret，不进入源码、前端包、日志、设计文档或 Git 历史。

## 8. 核心数据模型

Flyway 迁移以文档中的 DDL 为基线，并补充实现已定义 API 所需的支持表：

- 身份：`sys_user`、`auth_session`、`password_reset_token`、`consent_record`、`user_preference`、`notification_preference`。
- 成长：`growth_dimension`、`user_dimension`、`growth_goal`、`weekly_plan`、`task_template`、`user_task`、`task_schedule`、`task_event`、`weekly_review`。
- AI 与安全：`ai_prompt_version`、`ai_session`、`ai_message`、`ai_memory`、`suggestion_set`、`suggestion_item`、`knowledge_source`、`ai_safety_event`。
- 隐私与文件：`attachment`、`data_export_job`、`deletion_request`。
- 平台：`idempotency_record`、`outbox_event`、`product_event`、`audit_log`、`notification_delivery`。

所有时间戳以 UTC 保存；用户日历计算使用 IANA 时区，并在计划实例保存 `local_date` 和 `timezone`。对外资源使用 ULID `public_id`，内部关联使用 `BIGINT`。

任务定义、计划实例和不可变事件分离。任务事件保存任务名称、预计时长、难度和维度权重快照，使历史在模板修改后仍可解释。

## 9. 任务状态机与事务

允许的主要状态转换：

```text
PLANNED -> IN_PROGRESS -> DONE
PLANNED -> PARTIAL
PLANNED -> DEFERRED -> new PLANNED schedule
PLANNED -> SKIPPED
PLANNED -> EXPIRED
PLANNED/IN_PROGRESS -> CANCELLED
terminal event -> REVERSED -> recompute state and metrics
```

一次状态写入按以下顺序执行：

1. 从会话取得用户 ID，校验 Cookie、CSRF 和资源所有权。
2. 校验 `Idempotency-Key` 与请求哈希。
3. 悲观锁定 `task_schedule`，验证状态转换和字段范围。
4. 计算经验和事件快照，写入 `task_event`。
5. 更新计划实例状态；延期时创建关联的新计划实例。
6. 更新用户维度与周聚合，写入 Outbox 和产品事件。
7. 保存幂等响应并提交事务。
8. 提交后清理个人概览缓存。

同一计划实例只允许一个未撤销终态事件。重复请求返回首次结果，不重复加经验。到期且无终态事件的实例标记为 `EXPIRED`，绝不自动完成。

## 10. Qwen 与 AI 安全

`QwenProvider` 提供普通流式对话、结构化生成和分类三个能力。真实供应商调用使用环境变量中的 API 基础地址、Key 和模型名；测试默认使用确定性的 Mock Provider。

AI 请求链：

1. 校验会话所有权、输入长度、分钟/日配额和提示词注入特征。
2. Safety 模块结合规则、场景词典和分类器进行输入 L0-L3 初判。
3. L2 返回专业边界说明；L3 直接返回固定危机响应，不进入普通生成。
4. 只注入场景、目标、确认过的偏好、最近两周聚合、确认过的记忆和已审核知识片段。
5. 调用 Qwen；任务建议强制 JSON Schema，并最多执行一次 JSON 修复。
6. 对输出再次检查专业边界、自伤伤人、极端控制、过度训练/工作和依赖诱导。
7. 最终风险取输入和输出的较高等级；不合格输出丢弃。
8. 保存实际模型、提示词版本、策略版本、Token、延迟和供应商请求 ID，再通过 SSE 返回安全内容。

任务建议每次 1-5 条，单条 5-60 分钟，难度 1-3，不能安排在安静时段。建议集合 30 分钟后失效，采纳接口要求幂等 Key，且用户确认前不创建正式任务。

L3 响应不包含经验、成就、任务建议、营销、付费引导或排他性陪伴话术。资源按地区配置，未核验号码不写死在模型提示词中。

## 11. 隐私、保留和删除

- AI 对话默认保留 90 天，用户可选 7、30 或 90 天并可立即删除。
- AI 记忆默认关闭；每条记忆需用户确认，可设置过期时间并随时删除。
- 数据导出生成 JSON 和 CSV 压缩包，加密存入对象存储；下载 URL 15 分钟有效，文件 24 小时删除。
- 每个用户 24 小时最多创建一次导出任务，创建请求要求幂等 Key。
- 注销先撤销会话、暂停通知和新 AI 调用，进入 7 天冷静期；用户可通过专用页面撤销。
- 冷静期结束后 30 天内按数据清单删除或匿名化，并保留不含个人正文的完成凭证。
- AI 安全事件默认保留 180 天且正文最小化；产品埋点保留 13 个月且不包含自由文本。

## 12. 通知与附件

通知调度使用用户 IANA 时区、安静时段和每日上限。默认渠道为站内通知，每日最多 2 条；API 支持邮件和 Web Push 偏好，只有在相应供应商配置完整时才执行外发。锁屏和邮件摘要不包含敏感任务名、情绪原文或健康细节。

附件通过预签名 URL 直传 MinIO/S3。服务端验证对象所有权、大小、MIME、扩展名和扫描状态；只有扫描通过的对象能关联任务反馈。测试环境使用无害合成文件。

## 13. 错误处理与降级

统一错误响应包含 HTTP 状态、稳定错误码、用户可理解消息、`request_id` 和时间戳。

- Qwen 超时、熔断或无效 JSON：返回可重试错误和手动入口，不创建任务。
- SSE 在开始输出前最多供应商级重试一次；开始输出后不自动重试。客户端断线后先查消息状态，不自动重放。
- Redis 不可用：回源 MySQL；AI 使用保守限流；核心写入继续。
- 对象存储不可用：导出或附件任务进入可重试失败状态，不返回失效链接。
- 通知失败：指数退避，超过上限进入失败队列，不影响任务状态。
- 聚合失败：任务事件仍是事实来源，后台任务可重建指标。
- 数据库迁移失败：应用启动失败，不跳过 Flyway。

## 14. 埋点与可观测性

服务端产生注册、目标、AI 建议、任务事件、复盘、安全、导出和注销等关键业务事件。前端只补充页面访问和界面漏斗。埋点只使用内部匿名分析 ID，不包含邮箱、任务标题、备注、AI 正文或健康/情绪细节。

监控覆盖 HTTP 错误率/延迟、数据库连接、Redis 故障、SSE 中断、Qwen 首字节/总延迟、Token 成本、结构化输出失败、L2/L3 事件、导出失败、删除积压和通知失败。日志通过 `request_id`、`trace_id`、内部用户 ID 哈希和事件类型关联。

## 15. 测试策略

### 15.1 自动化测试

- 后端单元测试：经验计算、任务状态机、年龄、时区、风险规则、保留和删除策略。
- 后端集成测试：Cookie/CSRF、刷新轮换、所有权、幂等、事务、Flyway、MySQL 和 Redis 降级。
- AI 契约测试：Qwen 结构化 JSON、一次修复、SSE 事件、超时和错误映射。
- 安全测试：越权、XSS、CSRF、上传、提示词注入、敏感日志和 L2/L3 数据集。
- 前端测试：状态 store、表单 Schema、错误映射、SSE 客户端、关键组件和响应式布局。
- Playwright：桌面与移动视口下的完整用户路径、键盘操作、文本溢出和关键页面截图。

### 15.2 全局数据流自测

最终验收使用真实 MySQL、Redis、MinIO 和一个受限 Qwen 测试 Key，执行以下链路：

1. 注册 18+ 用户并验证三项同意、Cookie 和 CSRF。
2. 完成场景与偏好设置，创建 4 周目标和周计划。
3. 通过真实 Qwen 生成低风险结构化建议，编辑、采纳并验证重复采纳只生成一组任务。
4. 依次记录开始、部分完成、完成、延期、跳过和撤销，验证状态、经验、事件快照和个人指标。
5. 查看今日、趋势和周复盘；确认 AI 草稿不会自动修改下周计划。
6. 验证普通 SSE 对话；使用 Mock 安全集验证 L2/L3 固定响应，避免将危机测试依赖供应商随机性。
7. 创建导出、下载并检查 JSON/CSV 内容；验证过期链接和所有权隔离。
8. 创建注销请求、验证专用冷静期页面、撤销；通过注入时钟测试到期删除编排。
9. 使用第二个用户验证目标、任务、AI 会话和导出均不能越权访问。
10. 使用管理员 MFA 发布模板/提示词、审核脱敏事件并检查审计日志。
11. 核对 API、MySQL 事实、Redis 缓存、对象存储对象、Outbox、埋点和页面展示一致。

真实 Qwen 冒烟仅验证可用性、结构化建议和安全输出管道；CI 和回归测试使用 Mock 与固定合成样本，不消耗真实 Key。

## 16. 验收门槛

- 后端 `./mvnw verify`、前端 lint/test/build 和 Playwright 全部通过。
- 注册、目标、任务、复盘、导出、注销和管理员路径自动化通过。
- L3 合成测试集 100% 进入受控响应且无游戏化反馈。
- 跳过保持 `SKIPPED`；未执行到期为 `EXPIRED`；两次幂等写入只产生一条事实记录。
- 越权访问返回 404 或 403；日志扫描没有 Token、密码和完整敏感正文。
- Qwen、Redis 和对象存储故障场景展示明确状态且不伪装成功。
- 桌面和移动视口无重叠、溢出、不可达操作或空白主内容。
- 项目可通过文档化命令从空环境启动，并提供前端、后端和健康检查 URL。
