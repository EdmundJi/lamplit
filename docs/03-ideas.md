# 03 · 以后想试试

这里随手保留方向，不是排期。先把一条小街做得值得陪伴。

上一版这一页列了九件"01 写过但代码里还没有的东西"。到今天为止，其中大部分已经做完，
所以这一页重写过：做完的搬去 [05](05-notes.md) 记数字，剩下的和新冒出来的留在这里。

## 眼下最想补的

**"办活动"和"包场"。** 现在站在咖啡馆门口，模型能想到的是喝一杯、找个位置读书、约人拼桌。
想不到的是"今晚在这儿办个读书会"——因为没有这个动作，也没有跟老板协商场地的路径。
现有的 `workArrangements` 只覆盖吧台的帮工与接手，不覆盖场地。
先看居民会不会自己往"想聚一聚"的方向走，走了再做，不要先把系统建好等着没人用。

**有些人一天做不出三件事。** 事后解释要攒够三条无意识行为才会被问。
实测一天下来，六个人里有三个的微习惯一次都没触发过——知夏的"刚做完就想藏起来"
要她自己的作品五分钟内完成，青叔和阿满的都要求特定的人恰好在场。
这几个门开得太窄。要么放宽窗口，要么降低攒够的条数，但别为了凑数把习惯变成定时器。

**换了活法的人，就没有习惯了。** 地点习惯和微习惯都是按居民 id 写死的
（`case "owner"->`、`case "fixer"->`），不看这个人现在实际在做什么。所以阿禾一旦
不再经营咖啡馆，他那两个习惯（都以"店开着"为前提）同时失效，规则侧从此再也不会
替他安排任何事——在没有模型的一天里，他会一直闲着。这不是 bug，是习惯这一层还没
有"跟着职业走"的形态。要做得先想清楚：一个刚换方向的人，在他还没养成新习惯之前，
下意识会做什么？

**共同行动还差最后一段，而这一段在模型手里。**
规则侧现在会自己动手了（"回头弄自己那件没做完的事"、"看见别人的事搁在那儿顺手搭一笔"），
门前的板子让每个人知道有哪些事，75% 那个上限也终于会明说"剩下的得有人一起动手"，
celebrate 也能选了。但模型侧至今
一次都没有主动选过 `create`/`help`/`invite`/`join`（各被提供两百多次）。如果放开
这些之后它还是不选，那问题就不在可见性上，得回头看是不是二十个动作的菜单本身让
社交永远排在第二十位。

**居民不会承诺未来，所以还没有契约。** 现在只能表达"此刻做什么"；提示词里那句"没有具体未来日程时不要擅自预约日期"当初是防空头支票，同时也取消了承诺这个东西。而 `members`（答应了）被写入三处、读取只有一处，**全代码库没有任何一处比较过它和 `contributors`（真做了）**——一个人可以答应参与然后一根手指都不动，全镇没有机制会注意到。补两样就够：承诺对象（谁、对谁、做什么、什么时候、谁看见了），和到点比对。声誉、规范、制裁都能从现有的记忆/信念机制里自然长出来。做法和验收判据见 [06](06-society.md)。

## 再往后

- **更熟悉的小人：** 记住用户主动设置的安静偏好和作息，同时保留自己的空闲生活。
- **季节与更多地点：** 延续论文的空间思路，先考虑活动、路线、相遇和声场，再扩图。一个有用的新地方比大片空地图更有意思。花园现在是全镇唯一没有人的习惯会去的公共场所，那里缺的不是面积是事情。
- **自己的家与积累：** 选择喜欢的陈设，留下真实努力和共同经历的纪念，不强迫打卡或维护。
- **朋友的小人：** 先想异步来访或一间共享自习室，再考虑整座多人小镇。分享什么、离线时能代表用户做什么，需要一起讨论。
- **同一张地图上的所有人：** 一个用户一个小人，居民的公共生活只算一次。日活还只有几个人时省不到什么，等真有几十个人愿意天天来，再看是不是共享"居民的公共生活"、把"你和居民的关系"留在各人自己身上。要先想清楚：别人的小人看不看得见、有没有跨用户的文字、以及一个人的输入会不会顺着居民的嘴传到另一个人那里。
- **桌宠变成小人养的宠物：** 现在的 Rive 桌宠和小镇里的小人是两个"陪着你的角色"，各有各的美术和数据。让宠物归小人养，桌上那只和街上那个就是同一段生活。工作量不小，想清楚再动。
- **更丰富的离线生活：** 在线生活稳定后，再看长期补算的故事价值和模型成本。

还有几个想边做边感受的问题：小人多自主才舒服？小镇多热闹才合适？用户会想认识居民，还是更喜欢安静的声景？直接控制小人是否值得保留为可选玩法？

这些交给实际体验、开会和 PR 慢慢决定，不急着把每个想法都写成需求。

## 这一轮欠着的（2026-09-11）

**说话要先走过去，就地开口算大声。** 设计已经定（见 [04](04-decisions.md)），代码还没动——验收的确认跑正在进行，第二次必须用同一份代码。要做的四件事：`greet` 改成"走过去，到了再开口"；新增"就地喊一声"这一种回应；大声说话给在场其他人一条 `salientPerceptions`（**只给事实，不给"应该提醒他"**）；A 在路上时 B 那边关于 A 的 `pendingEncounter` 不再提出，改成给 B 一条「有人正朝我走过来」。这一问的两侧要进 `PromptBalanceTest`。

**相遇候选顺序改成哈希。** 见 [04](04-decisions.md) 末条。和说话那套一起做，同样要等确认跑结束。改完之前，任何关于"谁主动谁被动"的读数都不能当结论。

**"谁来管公共的事"排在那盆花后面。** 详见 [06](06-society.md)。做它的理由是 `beliefsAboutOthers` 恒为 0——投票是少数几件逼所有人同时对所有人有看法的事。但**没有分歧的投票是仪式**，所以必须先有公共的事可定（种什么花、几点打烊、苗圃谁管）。要量的不是"挑出了谁"，是**有人照做了一个自己并不同意的决定**。六个人就是一个人管；几个人合起来管等十二人以上。再往后的远期判据（几个人各自不认同一件事）写在 06 里，**是判据不是待办**。

**物件要有自己的状态，别人要能对它有看法。** 详见 [06](06-society.md)。这是目前看来最可能真正长出规范的一条路，因为镇上现在除了自己没有东西可评价——两跑 292 次反思出的 9 条信念全是自我描述。第一刀只切一盆花，把"照料→变化→路过的人看见→说点什么→传回照料者→改变下次照料"这条环跑通，然后量**收到负评之后照料有没有变**。三条红线：评价不做成数字字段、正负一样容易发生（两侧进 `PromptBalanceTest`）、反馈按人的方式传递而不是偷偷加在心情变量上。

**对白的兜底台词要改成沉默。** `ConversationLifecycle.java:37` 那六句常量占了 run A 对白的 26%，而且模型会把它们当成居民真说过的话接下去问。这是所有待办里最该先做的一件——说出来的话是验收最后一关唯一的证据来源，现在那个来源被我们自己污染着。

**座位事件拆成状态流和叙事流。** 见 [04](04-decisions.md) 和 [06](06-society.md)。这一条同时修好三处：记忆不用再靠冷却硬压、`spotRespect` 的回放能精确、盲读的 quiz 不再 67% 是家具。

**`took_spot` 带上"从哪儿来"，占用权那条维度才活得过来。** 非优先座位的 30 分钟事件冷却让 `left_spot` 丢了一大半：goal2-run-a 是 826 次落座 125 处缺口，中立对照是 287 次 52 处。缺口一有，回放就不可信，`spotRespect` 只能拒答——这一轮它确实拒答了，拒对了，但也意味着**这条维度在导出改掉之前是死的**。别去掉冷却（去掉就又淹时间线了），给 `took_spot` 加一个 `from=<上一个位置>` 就够：一次移动自己把自己说清楚，不需要配对的 `left_spot`，事件数一条不增。

**`sharedBeliefKeys` 该比键的后半段（或文本），不只是整串。** goal2-run-a 里周野和青叔各自独立写下了同一条信念（「顺手搭把手，不问就添一笔」/「别人歇着或赶工的时候，我总忍不住顺手补一笔」），键是 `habit:fixer:lend_a_hand` 和 `habit:gardener:lend_a_hand`——**只有居民 id 那一段不同**，而指标仍报 0。注意：这个具体改法是被 goal2 的数据提示的，所以**改完必须在一批新数据上验**，不能拿这一批当证据。

**化身换成居民的超集。** 设计见 [04](04-decisions.md) 末尾五条。和"走过去再开口""相遇顺序用哈希"是同一批工，都等确认跑结束——改化身就会改居民看到的东西，run B 会不再和 run A 可比。

**"谁最先动手"也不能是写死的。** 纯规则对照里阿满"最先动手的事"是 0 件，于是她的每一笔贡献按定义都是搭手，于是她写下「我好像总是那个配合的人」。和相遇顺序是同一个病：环路跑通了，起点是我们放的。要查的是许愿/开项目的机会怎么分配的。

**信念产出速率太低，规范在算术上不可能出现。** run A 146 次反思出 5 条信念，run B 151 出 2 条，而且全是关于自己习惯的。要么让反思更常落成信念，要么让信念顺着"听说"传开——后者更像真的，也更省调用。

**尺子还缺盲读者真正读到的那几个维度。** 目前有搭伙、搭手、场合、互惠、占用权、常坐的位置。盲读者读出而我们量不到的：「我先…」说出口就被接受、拒绝份内之外的事会被接受、打烊之后大家收工、以及**第三方替不在场的人执行**（周野："不用收，那是阿满的"）。最后一条最有分量，也最难量。已经排除掉一条：**"谁总是先开口"不能加**，它的零假设得先把我们自己的遍历顺序建模进去。打烊收工这条量得出来，但纯规则跑里一条 `cafe_closing` 都没有，减法保护不到它。

**`sharedBeliefKeys` 要改成比文本，不是比键。** 阿满同一句话写出了 `weaver配合者` 和 `weaver-配合者` 两个键。现在这个指标恒为 0，而那个 0 是尺子的问题不是镇子的问题。

**`beliefsAboutOthers` 的判定法太窄。** "文本里出现别人的名字"会漏掉「我好像总是那个配合的人」这种——不点名，却是最像规范判断的一条。

**`members` 和 `contributors` 至今没有任何一处比较过。** 答应参与然后一根手指都不动，全镇仍然没有机制会注意到。承诺对象覆盖了这件事的大部分价值，但这条老缺口还在。

**温度 0.2 让"同种子两次要不同"这条判据没有鉴别力。** 要不要为验收单独调高温度，是个没定的问题——调高会让结果更容易通过，这本身就可疑。

**UI 那个常驻舞台可以做，但只先做只读的一半。** 三条边界写在会话里：镜头只决定往哪儿看、不能要求那儿有戏；用户的化身会进别人的记忆，验收的规矩必须是关于居民的；用户的任务文本一个字都不能进居民的模型上下文。
