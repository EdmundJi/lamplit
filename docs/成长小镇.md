# 成长小镇

「成长小镇」是把平台里已有的数据变成一条像素街道：每个用户一栋楼，好友是邻居，中间是所有人共用的成长学院。它不新增任何后端概念，只是换一种方式看目标、任务、属性、等级、连续记录和好友关系。

## 画面里的每样东西都对应一条数据

| 画面 | 数据来源 | 规则 |
| --- | --- | --- |
| 门面（书店 / 健身房 / 公寓 / 冰淇淋店 / 面包房） | `/insights/attributes` 里经验最高的维度 | 知识 → 书店，健康 → 健身房，职场 → 公寓，关系 → 冰淇淋店，心境 → 面包房 |
| 楼层数 | `overallLevel` | 每两级加一层，最多四层中间层 |
| 卷帘门是否放下 | 今日任务状态 | 自家在休息日仍开门欢迎；邻居沿用今日活动映射 |
| 屋顶装置 | `longestStreak` | 3 / 7 / 21 天各解锁一件，中断不会拆除 |
| 配色（红 / 蓝 / 橄榄） | `publicId` 哈希 | 同一栋楼所有模块共用一个色系 |
| 小人在做什么 | 今日任务状态 | 已完成 → 去学院读书；进行中 → 在学院看手机；只有计划 → 在家门口踱步；没有安排 → 待在家 |
| 头顶表情 | 同上 | 星星 / 省略号 / 叹号 / Zzz |
| 名牌上的称号 | `equippedTitle` | 只有自己的房子显示 |
| 邮递员的信 | `/friends/unread-summary` | 有未读消息时头顶出现信封，点开可跳转到聊天 |
| 小助（学院门口的向导） | 今日状态 + 鼓励文案 | 点开显示一句建议，跳转到 AI 助手 |
| 学院 | 所有已完成任务的邻居 | 点开显示今天在学院读书的人 |
| 晨昏 | 用户时区 + 服务端校时 + 季节 | 光照与灯光连续变化，可手动预览昼夜并恢复随时间 |

独自升级模式打开时只显示自己的房子和学院，不拉取好友资料。

## 小镇社会：限知与传播

镇上住着 18 个 NPC，分三层：**第一层 2 个**（小助、邮递员，会向你索取回应）、**第二层 6 个**
（可以搭话但从不索取，各自绑一个成长维度）、**第三层 10 个**（纯背景生命，不可对话）。玩家的认知
负担只有 8 个，因为第三层根本不请求注意力。

**一人一镇**：每个用户有自己独立的 18 个 NPC 和事实库，NPC 的知识只关于「一个玩家 + 其他 NPC」。
不做共享世界——共享之后每个 NPC 要同时处理多个玩家的事实，限知模型立刻失控。

核心不是 NPC 数量，是**每个 NPC 只知道他该知道的那部分**：

1. **事实采集**：玩家事件先过 `TownNpcPerception` 模糊化，落进 `town_fact` 的只有「他在镇上已经
   小有火候」这类句子——**原始数字、任务标题、具体时刻一律不出现**。
2. **目击判定**：物理在场（在场轨迹 × NPC 日程的时空交集）才算看见。半夜一个人完成任务时全镇
   没有一个人在场，于是只有小助知道。
3. **传播模拟**：按日程重合生成当天的相遇序列，逐条事实算传播概率
   `f(亲密度, 说话人分享欲, 听话人好奇心, 兴趣重合, 显著度, 癖好)`，纯函数、固定种子可复现。
4. **转述走样**：每一手的文本由 LLM 批量生成，hops 越大越模糊越夸张；`NAME_MIXUP` 之类的癖好会
   造成张冠李戴。网关不可用或太慢时逐条回退确定性模板，整条链路不依赖 LLM 可用性。

**小助全知但不八卦**：它拿得到全部事实，但每一条 knowledge 都标 `no_relay`，并且整个退出传播
网络——不参与相遇、不当二传手。所以它的 talking-points 恒为空：它对你说话，不对外传话。

**树洞与牵挂**（表已建，行为属 M4）：`town_bond` 带有向、隐藏的 `regard`，玩家节点永远不参与
（库里有 CHECK 约束焊死）；`town_confidant_thread` 与传播链的任何表都没有关联。

代码入口：`TownSocietyService`（装配与 SQL）、`TownSocialSim`（纯函数：亲密度、传播概率、传播链）、
`TownNpcSchedules`（向后兼容的整点时段 `schedule`）、`TownNpcRhythm` + `TownDayPlan`（M7：节律与
分钟级行程，见下）、`TownRetellGenerator`（转述，Qwen + 模板兜底）、`TownSocietyJob`（每晚 03:45）。
接口见 `成长小镇-接口约定.md` §3.5 与 §7。

## NPC 的一天：节律与通行（M7）

**病灶**：改造前的日程是「时段 → 地点」，NPC 到点就出现在那个地点站着，一天七个格子，没有
"正在去"的概念。M7 把它换成「行程 + 通行」：一天是一串要办的事（`errands`），事情之间的路上
时间是真实的（`legs`），NPC 沿街慢慢走过去，而不是瞬移到目的地。

- **节律**（`town_npc.rhythm`）：这个 NPC"平常的一天"——几点起、几点睡、常去哪几处、每处待
  多久，由五维度兴趣与性格（分享欲 × 好奇心）在建号时算好、此后不变。`TownNpcRhythm.defaultFor`
  是纯函数，18 个人各自不同，互不雷同。
- **当天行程**（`TownDayPlan`）：节律 ± 当天偏离，`seed(npc_code, date)` 决定，可复现。偏离的
  输入来自心情（低落时少出门）、天气（雨天户外行程缩短）、对玩家的亲密度（顺路加一件小事）、
  活动（`town_event`，M4 落地前恒为空）。同一个函数产出 `errands` + 推导出的 `legs`，暴露
  `positionAt(plan, 分钟)` 告诉调用方这一刻该把人画在哪儿——纯函数，输入只有
  `(npc_code, rhythm, 当日上下文, date)`。
- **相遇判定**：不再是"同一时段同一地点"，改成两条分钟级时间线按 `positionAt` 比对，分
  `CO_LOCATED`（同处停留）/`EN_ROUTE`（路上相遇）/`PASSING`（擦肩）三类，传播权重依次是
  1.0/0.6/0.3——路上也能传八卦了，不再只能在咖啡馆里换情报。`home` 永远不算相遇。
- 接口：`GET /town/npcs` 每个 NPC 在原有 `schedule` 之外新增 `dayPlan`，两者同时下发，前端按需
  切换渲染方式。

## 观察模式

HUD 上的「观察小镇」把镜头从玩家身上摘下来，在广场、学院、公园、咖啡馆、健身房之间缓慢巡游
（每处停 6 秒、平移 4 秒，三个兴趣点正好 30 秒一圈）。镜头停下来时，画面里的 NPC 会说出他自己
知道的那几条——两个人说的必然不一样，限知在这里是看得见的。既是录 demo 的工具，也是一个真功能。

## 玩家操作

- 拖拽平移、滚轮缩放；点房子或小人看它背后的数据。
- 点地面：自己的小人走过去；点 NPC 或学院：走到跟前再触发对话/进门。
- 方向键或 A/D 直接控制自己的小人。
- **奔跑**：按住 Shift 移动（112 px/s → 264 px/s，走路动画同步加快到 1.6 倍）；触屏用 HUD 上的「开始奔跑」开关，开着时所有移动都跑，Shift 无论开关都能跑。速度常量与纯函数在 `town/walkers.ts`（`WALK_SPEED` / `RUN_SPEED` / `moveSpeed` / `stepToward`），有单元测试。

## 素材与授权

美术来自 LimeZu 的 Modern Exteriors 和 Modern Interiors，授权允许商用与开源项目使用，但禁止再分发。因此：

1. 原始 zip 放在被忽略的 `tmp/` 目录，生成的 `frontend/public/assets/town/` 也不进入版本库。
2. 新环境先运行 `python3 scripts/build-town-assets.py`（需要 Pillow），再启动前端。
3. 页面底部保留 LimeZu 署名。
