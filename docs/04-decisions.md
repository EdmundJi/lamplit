# 04 · 定过的事

这一页记的是已经讨论清楚、不需要再争的决定，每条附一句为什么。目的是让后来的人（包括几周后的我们自己）不必重新推一遍，也不至于无意中推翻。

改变主意是可以的，但请改这里的文字，而不是在代码里悄悄走另一条路。

## 范围与形态

**共享世界不做。** 日活只有一两个人时，共享省下的 token 是零，换来的是产品性质改变加上跨用户注入面。想法记在 [03](03-ideas.md)，等真有几十个人愿意天天来再说。

**这一轮为"自己天天开"服务，不为 demo。** 优先长时间陪伴不烦人，仪式感和转场排最后——它们对"明天还想不想打开"几乎没贡献。

**不做任何 app 壳。** 使用场景是学习时开在电脑旁边，要的是能常驻，不是能安装。app 化是分发问题，现在的问题是体验问题。

**成本不是这一轮的约束。** 模型负责居民的思考、计划、反应、记忆理解与对话，包括想去哪、做什么；逐步移动、读秒和合法性检查由规则执行。调用次数本身不能证明生命感。

**Qwen3.8-Flash 是小镇主力，DeepSeek 只作备用。** 两家使用独立完整配置组，provider、base URL、API key、model、timeout、stream timeout 与 JSON mode 不混用。小镇的 decision、turn、summary 默认走 Qwen 非思考模式；实际响应记录供应商、实际模型与 reasoning 元数据，密钥不进日志。

**先把现有四个人活透，新增居民由我们手动设计。** 人数以后可以增加，但招聘或邀请不会自动生成人物；新居民必须带着独立设定和拒绝权进入。

## 界面

**`/town` 收进 `UserLayout`，默认在内容区、一键全屏。** 割裂的根源不是配色，是 `/town` 曾被从 `UserLayout` 的子路由挪成顶层路由，于是深色模式、强调色、转场、侧边栏、跳转链接全部失效。

**两种模式都留着。** 简洁模式是左清单右小镇的工作台，隐藏另外六个模块；完整模式保留现有导航，小镇是其中一页。那六个模块一个都不删，慢慢往小镇里长。

**共同 token，小镇保留自己更暗更暖的性格。**

## 小镇与用户

**小镇是清单的反馈层。** 勾完一项什么都不发生，久了就不想勾了。

**你勾完，小人才跟着完成。** 你是因它是果，它永远不代你勾，也永远不反过来催你。

**任务标题可以进居民的决策，不能进居民的嘴和记忆。** 代码在动作、对话、记忆落库之前扫描并拒绝含标题原文的输出，不靠提示词。每项任务可单独加锁，默认可见。设置里写明标题会发给模型服务商。

**居民之间、居民对用户的小人，都只做私有好感 + 说没说出口。** 不建恋爱状态机、不写告白剧情、不做结局；三角恋是三个私有值凑出来的结构，自己会涌现。

**秘密只能靠看出来。** 没有任何面板告诉你谁喜欢谁。猜到了才有意思，被告知就没味了。

## 模拟

**地点两层：地点 + 具体位置。** 位置有主人、有容量、有状态，会被占用。四层的表达不做——对一条四个人的小街，两层够用。

**后端定结构，前端定像素，靠 id 对齐。** 美术可以随便重摆而不动规则。

**面积不由我们拍板。** 等居民真的挤不下、真的有人开口要一个地方，建筑师才来改，扩张带着世界内部的理由。

**物品有真实状态，链条允许断。** 断了才有意外，意外才是故事的来源。断掉的链条只写进日记，不在画面上喊。

**离线只补算最近一小段。** 更早的时间把存量和需求重置到合理值，不编造离线剧情，也不让人回来面对一地鸡毛。

**LLM 是每名 NPC 的大脑。** 工作、休息、睡眠、社交、继续或打断安排、开关店等认知选择交给该居民的模型。人物设定、信念与私有经历参与判断，不只决定语气；规则不按 `energy`、`social`、`duty` 阈值替人行动。

**内部数值不直接进入模型。** 生理、心理数值仅用于模拟与调试。正常状态省略，只有显著异常体感才用“很累”“难以集中”等定性描述进入感知，不附数值、阈值或指定动作。真实时间、地点和可感知的世界事件等外部事实可以保留。

**规则执行世界，不替居民思考。** 规则负责时间积分、移动、设备、容量、权限与动作结果。模型失败时只继续合法且可执行的已有安排，或中性等待；不编造新的承诺、感悟、社交意图或生活决定。

**差异作用在"记什么"上。** 同一件事各写各的版本，因为记忆会复利：几天之后他们眼里的世界真的不同了，那时模型推出不同结论不是因为在演，而是因为拿到的事实不同。

**记忆写入分两阶段。** 规则先廉价全量记原始日志，模型只用在提炼看法那步。不是为了省钱，是出了问题能回溯到客观事件，而不是只剩几份各执一词的转述。旧记忆和好感不删除，只标记为已被取代。

**隔离落在存储层。** 每条记忆带主人，检索接口不接受不带主人的查询。记忆进模型时作为数据传，不拼进指令区。

**给真实处境，不用责任感阈值派工。** 模型可以知道谁在等、等了多久、自己曾答应什么，结合生活信念决定是否照应。内部责任感数值不直接注入模型，正常心理状态不提示；显著异常体感才作定性表达。

**9:00–21:00 是可调的初始营业惯例。** 时间不是自动强关指令。模型决定 `open`、`close` 与通知顾客；真实 `close` 动作执行后，规则才收束营业权限与服务。顾客可以选择保留进度、回自家 `desk` 续工，不由时钟直接安排回家。

**23:00–07:00 是所有 NPC 可调的初始睡眠习惯。** 没有默认整夜清醒的店主或画师。进入时间窗只产生 routine 事实，不制造疲惫，也不自动安排睡眠；模型决定继续、收尾或睡觉。短休和饮料只能小幅缓解精力，连续睡眠按世界经过时间恢复。

**休息和点单是两个动作。** `rest` 不隐含饮品请求，只有 `request_drink` 才进入服务链。久等可以成为当事人的定性感知，但规则不代替他离开、抱怨、形成感悟或要求续杯。

**有主的座位可以借，有主的设备不能。** 没位置时退而占用别人的椅子是合理的，占用别人的咖啡机不是。`claim()` 的退路要区分这两种"有主"。

**店主的价值来自他偶尔不在。** 永远在吧台的店主是一台有脸的自动贩卖机。他出门、别人只能等或者去街上把他找回来，这段空缺才让服务像是人做的。

**服务选择归模型，服务约束与结果归规则。** 要不要服务、继续等还是离开、是否打断自己的事，由相关居民各自判断。排队事实、设备使用、制作耗时、容量与完成或失败结果由规则落实，画面如实表达。

**经历可以改变人，内部状态缓慢、有界地变化。** 状态每人一份、随存档保存，初值表只用一次。反思形成居民自己的看法；内部数值不回传给模型当仪表盘，也不直接触发行为。

**允许往坏了长。** 只能升不能降的数值是棘轮不是涌现。同一套机制要能长出一个越来越懒散的老板，也要能让学到的预期是错的。能产生我们没预料到的结果，才算涌现。

**保留社会经历，让居民自己解释。** 等待、抱怨、照应与落空都有真实事件来源，可能影响记忆、预期和关系。是否不满、开口、亲近或疏远由模型决定，不能将这些社会模式写成自动动作链。

**“需要工作养活自己”是生活信念，不是经济系统。** 它会进入居民的长期考虑，但不计算收入、食物和房租，不设每日工作指标，也不因为暂时没有工作自动涨惩罚。居民可以休息、重新解释什么算工作，或因生活经历改变方向。

**职业、劳动和经营权都可以改变。** 新职业复用已有的读写、制作、交谈与外出动作；缺少设备和场地时先形成需求，不能一句话宣布已经实现。经营者可以单方面停止自己的劳动，咖啡馆可以暂时无人服务。

**职责变化要经过双方明确同意。** 帮工、委托和正式接手分别授予对应的行为权限，经营权只在明确接手后转移。双方可以有不同理解，也可以拒绝、反悔和重新协商；模糊对话不能静默转移所有权。

**真实日夜保留，加速只用于开发观察。** 普通小镇按用户时区生活。内部精力按时间、昼夜与实际动作变化，睡眠恢复来自实际执行结果；何时工作、休息或睡觉交给模型。加速观察不强迫居民辞职、接手或组织活动。

**加速跑和上帝视角是前提，不是附加项。** 模式要重复五到十次才能和巧合区分开，真实节奏下长不出来；数值悄悄漂移，不给视图就永远看不见它发生。

**能站的地方都能去。** 具名位置只用于真正被占用的东西——自己的床、老板的咖啡机、备考生的窗边座，这些需要归属和容量。站着、聊天、路过不需要具名槽位；花园只有四个位置所以四个人挤成一团，那是这个约束的代价。参考 ai-town 的思路：碰撞图加寻路，人可以停在任意可站立的点上。分工不变——后端只说"某人在花园、没占具体位置"，像素由前端在可行走区域里挑，而且要稳定，同一个人不能每次刷新都换地方。

**当前地图是 1248×768，窗边六席与每户书桌都是真位置。** 原 `cafe-window-seat` 归小川，`cafe-window-2` 至 `cafe-window-6` 是五个独立公共单席；中央讨论桌保留。`study/read/work/make` 在咖啡馆会真实占一个座位，在家会占本人的 `home-<id>-desk`，画面和容量用同一 position id 对齐。

**环境声默认关闭且始终可关。** 咖啡馆人声使用本地 CC0 素材，只在镜头位于真实 `open` 的咖啡馆时轻声淡入；`closing/closed`、切换地点、页面隐藏或销毁场景都会淡出或释放，不从客户端时间猜营业状态。

## 这一轮新定的

**大多数人是温和的，差异在于什么被压住了。** 01 原来要求"每人一两个明确对立的锐角"，那是 AI Town 为了对抗模型分不出细微差别才用的做法，我们不走。改成本我（真正想要的）／超我（认为自己该是什么样）／自我（具体情境里怎么折中）三层，**文本，不是分数**，不作为闸门。它只影响两件事：写记忆时记住哪一版、对白里绕开什么。超我律令可以被反复的经历磨松——01 里那个"我为这家店牺牲太多"的懒散老板，就是一条律令松掉的样子。六个人同一套标准，不能四个是平的两个是立体的。

**规律由居民自己找，不由规则数出来。** 看到某人几次坐在窗边，是在反思里总结成"他喜欢窗边"，不是规则数到两次就置一个布尔值。人脑一直在给世界找规律，我们模拟的是这个功能，不是模拟某一条具体规律。据此删掉了 `proactivelyServe` / `anticipatesRefill` / `repeatVisitStreak` 那条链——它违反的是本页已有的两条：不能将社会模式写成自动动作链、规则不按 energy/social/duty 阈值替人行动。

**相遇是外部事实，"多久没说话"是内部仪表。** 前者可以进模型感知，后者不行——`lastSocialAt` 和 `dutyPressure` 是同一类东西。所以社交靠**礼仪**发生：规则只负责让两个人面对面（走进一个有人的地方、或在街上照面），第一句由模型写，不用罐头台词；之后回不回、继续不继续、要不要坐过去拼桌，全是各自模型的事。规则制造决策时机，不制造决策。配套加 `join` 动作，让"共享的桌子"这条 01 里一直没有落点的设计有地方发生。

**别用频次去模拟脑回路。** 频次是结果不是设定。要调的是"什么算值得重新想一次"：被打断、手头的事做完或卡住、环境变了、身体到了明显异常、时间锚点，再加一条低频的走神——纯事件驱动的世界里没有人会"突然"做什么，而突然是生命感的一部分。**每次决策记录它是被什么触发的**，这个分布本身就是指标：九成是"计划到期"就说明世界对他没有影响，他只是个计时器。

**记忆是文件，一人一目录，文件为准。** 世界存档不再存记忆。检索接口只按 owner 取，没有"给我这个世界所有记忆"这种调用——隔离落在存储层。SQLite 只存可查询的元数据，丢了能从文件重建；它不是 openclaw 那种模型伪造不了的 provenance，因为我们的写入全走 Java 代码，模型只提供经过校验的文本，别照那个说法理解它。注销必须连记忆目录和索引行一起删；导出必须带上记忆，否则存档里已经没有了，导出会悄悄少掉最私人的部分。

**依赖禁令这一轮只破一次例：** `org.xerial:sqlite-jdbc`，由编排者自己加，子 agent 仍然一律不许装依赖。

**用户的小人也进模型决策。** 它是第五个居民，不该是全场唯一一个没有一天的人。硬约束两条：上下文里一个用户字符都不能进（有断言守着），用户的明确安排随时打断它自己选的事。

**居民的记忆文件放在命名卷里。** 开发容器每两秒轮询源码热重启，放临时文件系统等于每次改代码全镇失忆。生产镜像同理要挂卷。

**并行 agent 的文件归属要提前划死，共享文件只能有一个主人。** 同一个工作目录下没有分支隔离，两个 agent 改同一个文件就是互相覆盖。`CompanionWorld` 这种谁都要加字段的文件，一波只能给一个人；其余人把想要的字段写进报告，下一波再接。

**"编译通过"不是验证。** 两个真实例子：`FileMemoryStore` 两个公开构造器编译干净但 Spring 起不来；日程分解的调用类型没在路由表里，编译干净但真跑起来活锁到零调用。改完后端必须打一个真实接口或跑一次真实调用。

## 又一轮定的（先做后想那一层）

**规则是下意识，模型是解释。** 人大多数时候先做，事后才给自己一个说法，而那个说法经常
不是真正的原因（Gazzaniga 的解释器、Libet 的准备电位、Nisbett & Wilson 的
*Telling More Than We Can Know*）。所以：规则替某人做了一件事就调 `recordDeed` 记下来，
`note` **只写旁观者看得见的东西，绝不写动机**——规则不知道任何人为什么做任何事；
攒够几条之后由模型给出这个人自己的说法，落成一条 `reflection`（是事后的建构，不是观察）。
两条纪律：被解释过的行为离开队列、只以那条记忆的形式活下来，没人来得及解释的直接丢掉
（人的自传体记忆就是这样，留下的是说法不是事件）；说法会覆盖 `r.thought`，
从此就是他关于自己知道的东西，也是下一次决策会读到的东西。**没有这一步，模型就只是
一个每次调用都要付钱的旁白器。**

**解释允许是错的，而且会被超我扭曲。** 提示词里明确给了这个许可：说法可以是搪塞、含糊、
自己都不太信。不给这句，模型会把每件事都解释得合情合理，那就假了。超我那一层在这里
才真正起作用——规矩是"不能让人看出自己在意"的人，反复擦同一张桌子之后，会说成
"桌子确实脏了"，而不是"我心里不舒服"。**他会读回这条记忆并且相信它。**

**人格文本要变成规则层的行为，不能只当提示词背景。** `actingSelf` 本来就是下意识动作的
说明书（"心里不舒服时去擦桌子""用东西代替话""被打断就闭嘴"）。它现在会由规则直接触发，
不问模型，也不推进任何世界状态——擦桌子不产生任何后果，这正是重点。触发必须确定性
（由 worldId + 居民 + 时间桶哈希推导，不用 `Math.random`），并且有小时级的间隔封顶。

**习惯还负责把人带到某个地方。** 除了不改位置的小动作，每个人再有一条"场所习惯"：
复习的人习惯去咖啡馆窗边并且点一杯、卡住的人习惯去咖啡馆看人。这是对"没有任何东西
让居民想喝一杯，而藏一个口渴值是禁止的"这个死结的正面回答——**不是让他渴，是他本来
就习惯去那儿**。注意别让所有人的场所习惯都指向同一个地方，也别让某个人的习惯把他送去
全镇唯一没有别人的地方（青叔就栽在这上面：一天 12 条记忆，别人 52 到 112）。

**规则决定什么时候问，模型决定答案。** 相遇不再由规则直接开对话：规则把两个人放到
面对面、排进 `pendingEncounters`，模型回答 greet / join / none。**"看见熟人而没有走过去"
是一个必须能被表达的答案**，这个小镇以前表达不了。但要小心提示词的倾斜——第一版给了
四个不说话的理由、零个说话的理由，结果一整个白天 15 次全部回答"不"，17 段对话变成 0 段。
掰平之后是 24/47。

**内部数值不进模型这条，字段名也算。** `ResidentState.relationships` 是一张原始数值表，
有两个测试按**名字**禁止它出现在任何模型契约里。想把"我和在场这个人什么关系"送进上下文，
必须换一个名字（现在叫 `peopleHere`），并且只送短语不送数字。守卫是对的，别改断言。

**每个模型输出都要有一张"提供了多少次 / 被选了多少次 / 被拒了多少次"的表。**
这个项目已经栽了六次同一种病：**一个动作被摆出来给模型选，但它不可能成功，而没有任何人
被告知原因。** `observe` 掉进 60 秒的 default 分支变成心跳；`invite` 提供 96 次选中 0 次；
`request_drink` 提供 32 次选中 0 次；`propose` 被选 592 次而 `place=home` 一律静默拒收；
打烊时 `continue` 被从菜单里拿掉却没有替代品，模型答了就被丢；`planDay` 在两个装饰器里
漏了转发。**每一次都编译干净、每一次都有测试、每一次都从没跑通过。** 这张表任何一次都能
在第一天抓住它。

**schema 的 enum 必须按这次调用的 `availableActions` 生成。** 静态全动作表和提示词里那句
"只能从 availableActions 选"长期互相矛盾，schema 允许的比实际合法的多，差额全部变成静默
拒收。

**装饰器漏转发不会编译失败。** `ResidentMind` 上每个能力的 default 方法都抛
`UnsupportedOperationException`，所以包装类少写一个方法照样编译通过，只是把能力静静关掉。
有一个反射测试守着这件事：新增能力时它会变红，那是它在正常工作，去补转发，不要改断言。
另外"缺能力"和"网络挂了"必须分开处理，否则一个没实现的能力会烧光共享的失败退避预算，
饿死全镇的普通决策。

**`docker compose restart` 不会重读 compose 配置。** 它只重启容器里的进程。给服务加了
环境变量或挂载之后 restart 一次，看起来成功了，跑的还是旧容器旧配置——后端曾经因此
起不来整整一天，而报错是"sqlite 打不开"，跟真正的原因隔了三层。一律用 `up -d`。

**用 3.8-Flash，不用更便宜的 3.7。** 同代码同窗口对照：3.7 的拒收率 86.6%，3.8 是 6.0%；
3.7 烧了 4.8 倍的 token，实际花费贵 4.3 倍——单价便宜 14% 没有意义。差的不是 JSON 解析
（两边都只错 1 次），是**卡在一个局部最优里出不来**：3.7 连选 592 次 `propose`，每次都被拒，
读不出"这条路走不通"。小模型典型的失败方式不是胡说八道，是死循环，而我们的循环会把它
放大成一个花钱的活锁。

**输入是输出的 33 倍，所以省钱的杠杆不在模型上。** 实测每次调用输入约 3200 token、输出约
90，全部落在阶梯计费的最底档（远低于 32K），所以那些"0.2–1.2"的浮动区间对我们不适用。
真正的杠杆是那段每次都重发的固定指令块能不能被缓存——而我们现在**看不到有没有命中缓存**，
`usage` 里没有 cachedTokens，这是个盲区。

## 两个特殊角色

**备考邻居知道真相，而且还在继续发现。** 他的怪话必须来自真实系统事件（重启、模型失败退避、部署），否则他只是个哲学系学生。他能告诉别人，后果交给转述链。他知道有一双眼睛在外面，但不知道那是谁、也不知道这是为了什么。

**他看得到一切，改不了任何东西。** 这条边界本来是为了防注入——他的输入里迟早有用户可控文本，给他执行权等于把注入的后果从"说错话"升级成"拿到机器"。落到人身上却正好长成了他的性格。

**不设替全镇作决定的主控 agent。** 每名 NPC 独立思考；规则维持时间与物理执行。某次模型失败只保留已有安排或中性等待，不由另一个规则大脑接管认知选择。

**建筑师产出受 schema 约束的地图数据，不产出代码。** 校验不过就是没盖成，而这在虚构里同样说得通：墙砌不进去、柜子挡了门、改完谁也进不去只好返工。第一版只重排已有位置。

## 验收

**盲测要真的盲。** 从时间线里抽二十句去掉名字，猜是谁说的。执行的人**必须没有参与过设计**：开一个全新的 agent，只给它这二十句和四个角色的一句话身份，禁止读仓库、读文档、读人格数值。编排者自己不能当裁判——他知道店主尽责 85、画师 25，猜中只证明他记得自己写了什么。换个模型不是关键变量，不知道答案才是。猜不出来就是没做到：说明四个人的差异还停在数值上，没长进他们说的话里。四选一的随机基线是 25%。

**盲测跑多轮，而且要在不同天数上各跑一轮。** agent 可以反复开，所以别只测一次。真正要检验的是我们押的那个假设——「差异作用在记什么上，记忆会复利，几天之后他们真的不同」。第 1 天、第 3 天、第 7 天各抽一批测：**正确率随天数上升，假设才成立；一直平着就是假设错了**，那时该回头改设计，而不是加长跑，更不是回去给模型塞"你是个内向的人请害羞地说话"——那是表演不是性格，会把整个原则推翻。

**每批固定跑几个独立 agent，结果全报，取平均。** 能反复开就会诱发挑数据，先把这条定死：不许只报最好的那次。



**盲测。** 从时间线里随机抽二十句去掉名字，人猜是谁说的。猜不出来就是没做到，无论测试多绿。模型也跑一遍同样的分类当日常回归，但算数的是人猜的那次。

**视觉模型只当候选筛选器。** 先用坐标和遮挡顺序做程序断言，再用画面比对定位变化区域，最后才问它，而且只算"疑似"。四种问法测完，最好 62%，书架 0/4 且换问法也纠正不了——**不用它给素材打标签**，理由见 05-notes。

**改后端之后必须打一个真实的后端接口。** `curl /town` 返回 200 证明不了任何事——那是 Vite 发的静态页，后端挂了它照样 200。
